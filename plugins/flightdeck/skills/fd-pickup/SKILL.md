# 작업 집기

도구는 `board` · `pick` 둘이다. 순서가 전부다.

## 1. 남들을 먼저 본다

```
board
```

살아 있는 세션 · 각자의 마지막 신호와 나이 · 지금 만지는 경로 · 선점 · 미확인이 온다.
"죽었다"는 표시는 없다. 나이만 있다 — 판정은 사람이 한다.

## 2. 무엇을 집을지 고른다

```
pick
```

인자가 없으면 **추천만** 한다(아직 선점하지 않았다). 1순위와 **왜 그것인지**,
**탈락 사유 전부**(없으면 큐는 블랙박스다), 후보 범위가 함께 온다.

## 3. 집는다

```
pick(item_id: "<id>")
```

선점하고 다음을 함께 낸다:

- 항목 본문
- **연결된 판단 전문** — 아래를 보라
- 브랜치 이름(항목 id 가 곧 브랜치다) + 워크트리 준비 명령

이미 자기 선점이면 거절이 아니라 **맥락 재출력**이다(컨텍스트가 날아가 돌아온 경로).

## 4. 계획을 세우기 전에 연결된 판단을 읽는다

`pick` 응답의 판단 절은 **본문의 대체재가 아니다.**
본문은 "무엇을"이고 판단은 **"왜 그렇게 하기로 했나"**다 — 무엇을 검토하고 왜 안 했는지,
어떤 근거가 거짓으로 밝혀졌는지, 어느 자리를 **일부러 안 고쳤는지**.

안 읽으면 같은 조사를 처음부터 다시 하거나, 더 나쁘게는
**의도적으로 남긴 자리를 결함으로 보고 고치러 간다.**

## 5. 겹침이 오면 조율한다

`pick` 은 경로 겹침을 **거르지 않고 알린다.** 겹치는 세션이 있으면 `note(kind: "ask")` 로
무엇을 건드릴지 알린 뒤에 시작해라.

## 안 하는 것

세션 등록(훅이 한다 — `session` 인자가 없다) · 브랜치·HEAD·sha 적기(서버가 git 에서 읽는다) · 락 획득(락이 없다).
