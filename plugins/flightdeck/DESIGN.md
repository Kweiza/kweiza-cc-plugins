# flightdeck — 설계

병렬 Claude Code 세션의 조정 계층. 서버 하나에 여러 프로젝트·여러 세션이 붙는다.

이 문서는 **구현의 공유 계약**이다. 여기 없는 것은 만들지 않고, 여기 있는 것은 이대로 만든다.

---

## 0. 왜 만드는가

한 사람이 Claude Code 세션을 10개 넘게 병렬로 돌려 한 제품을 개발하면, 세션끼리 대화할 수단이 없어
"저쪽이 뭘 집었나"를 추측하게 된다. 그 추측이 틀리면 남의 작업을 통째로 집는 사고가 난다.

기존 처방은 레포마다 셸 스크립트 네 벌(게시판·큐·핸드오프·대시보드)과 배타 락 다섯 종이었다.
그 구조를 8축으로 실측한 결과 병목과 뿌리 원인이 이렇게 나왔다.

**병목(세션 수 N에 대한 악화 순)**

1. **대시보드** — 조정 산출물 중 유일하게 공유되는 것이라 전 세션이 2회씩 편집한다(수요 = 2N).
   배타 단위가 카드 한 장이 아니라 파일 전체이고, 모든 커밋이 `asOf` 한 줄을 건드려 리베이스가 반드시 충돌한다.
2. **랜딩 락** — 검증 11단계 중 이미지 태그를 쓰는 것은 4단계뿐인데 전 구간이 잠긴다.
3. **큐 착수 경로** — 1차 필터가 죽어 있고(경로 정규화 결함으로 `Makefile` 이 자기 자신과도 안 겹친다)
   그 값의 출처가 브랜치 diff 라 **규율을 지킨 착수 직후 세션에는 정의상 비어 있다**. 첫 명령이 1분 걸린다.
4. **세션당 20회 넘는 수동 호출** — 자동 강제 지점이 사실상 둘뿐이고, 안 불렀다는 사실조차 안 남는다.
5. **계약 락** — 세션 발자국의 절반만 덮고, 실제로 난 사고(같은 날 개정 차수 충돌)는 **락이 원리적으로 못 지키는** 논리 카운터였다.
6. **스테이징 락** — 자동 반납이 없고, `guard` 가 자기 락의 `since` 를 갱신하지 않아 **긴 세션이 남에게 죽은 것으로 보인다**.
7. **게시판 조회** — 파일이 지워지지 않아 신호 대 소음이 단조 악화한다(실측 6%).

**뿌리 원인 여섯 중 이 설계가 겨냥하는 것**

- **파생 가능한 사실을 손으로 다시 적는다.** 누가 살아 있나 · 무엇이 랜딩됐나 · 어느 경로를 건드리나 · HEAD 가 무엇인가는
  전부 git 과 파일시스템에 이미 있다. 손으로 베낀 스냅숏은 원본이 움직이는 순간 조용히 거짓이 되고, 거짓임을 알려 주는 자리가 없다.
- **같은 사실을 네 저장소에 적는데 셋이 버전관리 밖이다.** 그래서 사용자와 다른 머신에 닿는 유일한 창이 대시보드가 되고,
  그 비대칭이 병목 1위를 만든다.
- **배타 구간을 불변식이 아니라 "무엇을 가드하기 편한가"로 정했다.** 그래서 모든 락이 동시에 너무 넓고 너무 좁다.
- **기계 필터가 관측 가능한 축이 아니라 뽑기 편한 축을 쓴다.** 도구가 자기가 무엇을 안 보는지 모르는 채 초록불을 낸다.
- **"저 세션이 살아 있나"의 정본이 없다.** 판단이 세 원천으로 갈리고 각각 다른 답을 낸다.
- **가드와 검산이 자발적 호출에만 의존한다.**

## 1. 원칙 셋 — 충돌하면 위가 이긴다

### ① 파생 가능한 사실에는 쓰기 API 파라미터를 만들지 않는다

검사가 아니라 **부재**로 강제한다. `--force` 도 `SKIP=1` 도 그 축에는 존재할 수 없다 — 우회할 필드가 없으므로.

지금까지의 처방은 전부 "적을 때 검사한다"(가드·검산)였고 실패 이유가 명확하다: 강제 지점이 둘,
우회가 넷, 거짓 초록이 셋. **틀리게 적을 필드 자체가 없으면 검사할 것도 우회할 것도 없다.**

이 원칙이 스키마의 세 계층(§3)으로 표현된다. 계층이 곧 쓰기 권한이다.

### ② 세션이 외워야 할 개념 수를 늘리는 기능은 만들지 않는다

성공 지표는 **세션당 쓰기 호출 수**와 **대체되는 규율 산문의 분량**이다.
도구가 늘면 규율의 뒤쪽(핸드오프·후속 등록·해제)이 먼저 빠지는 같은 붕괴가 새 이름으로 재현된다.

MCP 도구는 7개, 스킬은 4개, 에이전트·커맨드는 0개다.

**스킬이 셋이 된 근거(2026-08-04).** 원래 둘이었고 그 숫자에는 계산이 있었다 —
스킬 목록은 컨텍스트의 1%에서 절단되며 **덜 쓰는 것부터 버려진다**(§6). 그런데 `fd-setup` 은
정의상 **가장 덜 쓰는 스킬**(머신당 1회)이라, 그 계산대로면 절단 1순위다.

그래도 셋으로 늘린 이유는 **판정을 스킬에서 뺐기 때문**이다. 무엇이 없고 다음에 무엇을
해야 하는지는 `fd setup` 이 순수 함수로 판정해 내고(그래서 시험이 조합 전체를 돈다),
스킬은 묻고·승인받고·실행하는 얇은 껍데기다(52줄). 절단돼도 잃는 것은 그 껍데기뿐이고
`fd setup` 은 남는다 — 다른 둘은 잘리면 규율 자체가 사라지지만 이쪽은 그렇지 않다.

**넷째는 이 논거로 정당화되지 않는다.** 이 예외가 성립하는 조건은 "판정이 코드에 있고
스킬이 그 위의 껍데기"이며, 그 조건을 안 만족하는 스킬은 여전히 만들지 않는다.

**⚠ 넷째가 생겼다(2026-08-06). 위 문단은 지켜지지 않았다.** `fd-update` 가 커밋 `cdce59d` 로
들어와 **§1 머리줄의 수가 하나 늘었다.** README 는 이미 그 수로 적고 있었고 이 문서만 낡아
있었다. **위 문단은 지우지 않는다** — 그것이 판정의 기준이었고, 넷째가 그 기준을 어떻게
벗어났는지가 이 항의 내용이다. (수와 이름 목록의 진실 원천은 이 절 머리줄 하나다. 여기에
현재형 수를 다시 적으면 그것이 또 낡는다 — 이 항목의 뿌리가 정확히 그 모양이었다.)

`fd-update` 는 셋째의 예외 논거를 **그대로는** 못 쓴다:

- `fd setup` 은 서브커맨드로 존재하고 판정을 순수 함수로 낸다. **`fd update` 는 없다.**
  갱신 판정은 `fd status` 첫 줄 · `fd doctor` · `fd selfcheck`, 그리고 **fd 밖의
  `claude plugin list`** 넷에 흩어져 있고, 스킬이 든 것은 **그 넷을 어떤 순서로 부르고 어디서
  멈추는가**다 — 즉 규율 산문이고, §6 이 "스킬에 넣지 않는다"고 못박은 바로 그것이다.
  72줄인 이유가 이것이다.
- 셋째의 완화("절단돼도 잃는 것은 껍데기뿐이고 `fd setup` 은 남는다")도 여기선 성립하지 않는다.
  잘리면 **순서가 통째로 사라진다.** 그 순서를 코드로 가진 명령이 없기 때문이다.

그럼에도 남긴 근거는 계산이 아니라 **사고**다. 갱신은 머신당 드물지만 틀리면 **조용히 오래
틀린다** — 수동 빌드 서버가 19시간·115커밋만큼 낡은 채로 `healthz=ok` 를 내며 돌았고 아무도
몰랐다. 그 사고 뒤에도 순서를 어디에도 안 적으면 같은 일이 반복된다.

**그래서 이 항은 예외가 아니라 부채로 적는다.** 근본 수리는 판정을 `fd update`(또는 `fd doctor`
확장)로 빼서 스킬을 다시 껍데기로 만드는 것이고, 그때 세션 스킬 예산 안으로 돌아온다.
다만 **플러그인 축은 fd 가 아예 못 잰다** — `cmd/fd` 어디에도 `claude plugin` 호출이 없고 버전
축은 `SkewBanner`(클라이언트 API 판 vs 서버 API 판)뿐이라 "마켓플레이스에 더 새 판이 있는가"는
원리적으로 답이 안 나온다. 그래서 `fd update` 로 빼도 **그 한 축은 스킬에 남는다.**
다섯째를 만들 때 이 항을 근거로 쓰지 마라 — 여기 적힌 것은 정당화가 아니라 **아직 안 갚은 빚**이다.

**줄 수 상한도 함께 다시 적었다**(`cmd/fd/plugin_test.go`). 앞선 판은 "스킬 목록은 항목당
잘리므로"를 60줄의 근거로 댔는데, 그 문장이 맞다면 **본문을 아무리 길게 써도 목록은 안 밀린다**
— 근거와 결론이 안 이어진다. 그래서 상한을 "부른 턴의 예산"으로 다시 세우고 호출 빈도로
갈랐다: 매 세션 부르는 둘(`fd-pickup`·`fd-handoff`)은 60줄 미만, 머신당 1회인
둘(`fd-setup`·`fd-update`)은 80줄 미만.

**⚠ 그 재정의가 기대는 플랫폼 동작은 아직 안 쟀다 — 측정 전 잠정이다.** "목록에는
frontmatter 의 `description`(§6 의 항목당 1,536자)만 실리고 본문은 스킬을 부른 뒤에 실린다"는
이 문서와 그 시험 주석 말고는 근거가 없다(§13 「아직 아님」에 올려 뒀다). 앞선 판이 두 축을
섞은 자리를 **또 다른 미측정값**으로 메우지 않으려고 여기 적어 둔다. 상한 80 을 지탱하는 실질
근거는 회귀선(지금 72줄이고 더 늘면 `fd update` 를 만들지를 다시 판정한다)이라 이 측정과
무관하게 선다.

그리고 **스킬 전수**를 그 표에 물렸다 — 이 항목의 뿌리가 "넷째가 목록에서 빠진 채로 아무도
안 세었다"였기 때문에, 다섯째가 생기면 시험이 먼저 빨개진다. 문서의 수도 정규식으로 **모든
출현**을 본다(어딘가에 옛 수가 남아 있으면 실패다 — 개정 블록을 얹는 이 문서의 습관이 정확히
그 구멍을 만든다).

### ③ 정합성 경로는 REST, MCP 는 그 위의 얇은 껍데기

둘 다 같은 순수 함수를 부른다. 두 벌이 아니다.
REST 가 없으면 서버를 만지는 순간 전 세션의 조정이 끊기고, 나쁜 스키마 변경으로 크래시루프에 빠졌을 때
되돌릴 경로가 사라진다.

## 2. 배치

### Tier A (이 문서의 범위) — 컨테이너 1개, 러너 0, 시크릿 0

```
[서버 머신]
  컨테이너 flightdeck   (Go 정적 바이너리 + SQLite, 볼륨 1개)
    :7420  GET  /                서버 렌더 HTML 한 장 (읽기 전용 대시보드)
           GET  /events          SSE
           POST /api/v1/...      REST (정본)
           GET  /healthz         {ok, api_version, db_ok, disk_free_pct, self_update}
           GET  /metrics         Prometheus
    -v ~/.flightdeck:/data  →  /data/fd.db   (SQLite, WAL, busy_timeout=5000)
                               /data/journal.git  (판단 백업 bare 레포)
                               /data/logs/

[모든 세션 머신]
  플러그인 flightdeck
    bin/fd          클라이언트 (셸 런처 → 캐시된 정적 바이너리)
    .mcp.json       stdio MCP: ${CLAUDE_PLUGIN_ROOT}/bin/fd mcp
    hooks/          5종
    skills/         3개
```

**MCP 를 로컬 stdio 로 두는 것이 첫 결정이다.** 원격 http MCP 는 끊기면 재연결 실패 후 전 세션이 수동
재시도를 요구한다 — 서버 장애를 도구 계층까지 끌어올린다. 로컬 프로세스는 끊기지 않고, 원격 장애는
**도구가 열화 결과를 명시적으로 반환**하는 형태로만 나타난다.

### Tier B (다음) — 러너 + 레인

머지 큐(rebase → 검증 → 병합을 서버가 순차 수행)와 실행 레인(스테이징 반입·e2e).
`landing`·`docs-land`·`staging` 락이 여기서 소멸한다.

**~~착수 선행 조건은 검증 명령 3회 실측이다~~ — 그 실측은 끝났고, 이 조건은 해소됐다.**

측정 결과(`fd-ci-timing-baseline`): **ρ ≈ 0.05**(랜딩 락 구간) ~ **0.09**(스테이징 포함).
경보선 0.7 의 **1/8 이하**이고, 가장 비관적으로 잡아도 0.16 이다.

따라서:

- **큐가 발산할 위험은 없다.** 발산을 이유로 Tier B 를 미룰 근거가 사라졌다.
- **Tier C(범위 축소)는 Tier B 의 전제가 아니다.** 범위 축소는 ρ 를 낮추는 수단인데
  낮출 것이 없다.

**다만 이것은 "해도 된다"이지 "해야 한다"가 아니다.** Tier A 핸드오프가 Tier B 를 미룬
진짜 사유는 발산이 아니었다 — 심사 세 건이 판정한 것은 **러너 · cosign · 도커 소켓
무인 실행 · GHE push 를 한꺼번에 안는 것이 1인 운영자를 착수 못 하게 만든다**였다
(§11 의 "전부 아니면 무로 제시하면 1인 운영자가 착수하지 못한다"와 같은 판정이다).
그 판정은 이번 실측으로 **바뀌지 않는다.**

즉 이 실측이 치운 것은 **가짜 장벽**이고, 실제 판정은 이제 **"저 선행들을 어떻게 쪼개는가"**다.

#### 러너 없이 떼어낼 수 있는 조각이 있다 — 착수한다면 여기부터다

Tier B 가 만드는 값을 선행별로 갈라 보면 한 덩어리가 아니다:

| 조각 | 무엇을 없애나 | 러너 | cosign | 도커 소켓 | GHE push |
|---|---|---|---|---|---|
| **① 랜딩 순서 큐** — 서버가 "지금 랜딩해도 된다"를 **순서대로** 내준다. 검증은 세션이 자기 자리에서 돌리고 결과를 보고한다 | `landing`·`docs-land` 락의 경합 | — | — | — | — |
| ② 서버가 검증을 돌린다 | 사람이 CI 를 기다리는 시간 | 필요 | — | 필요 | — |
| ③ 서버가 병합·push 한다 | 손 머지 실수 | 필요 | — | 필요 | 필요 |
| ④ 실행 레인(스테이징·e2e) | 스테이징 락 | 필요 | 필요 | 필요 | 필요 |

**①은 선행 넷 중 하나도 안 쓴다.** 서버는 이미 항목·선점·세션을 갖고 있고, 랜딩 순서를
내주는 것은 그 위의 조정이지 실행이 아니다 — 지금 있는 것(발번기·선점·이벤트 원장)과 같은 종류다.
그리고 ρ 가 0.05 라는 것은 **①만으로도 큐가 안 막힌다**는 뜻이다.

그러니 "Tier B 착수"를 ①②③④ 한 덩어리로 다시 제시하지 마라. 그 제시 방식이
착수를 막은 원인이었고, 실측은 그 원인을 건드리지 않았다.

**①은 착수됐다(2026-08-05).** 랜딩 순서 큐가 실물로 존재한다 — `landing_queue`(순서) 와
`resource_hold`(배타, 자원명 `landing`)를 잇는 전이가 서버에 있고, 세션은 `land` MCP 도구·
`POST /api/v1/landing`·`fd land` CLI 로 줄에 서고 차례를 받고 다 쓴 뒤 보고·이탈한다.
물린 레인은 사람이 `fd lane release`(`POST /api/v1/landing/rows/{id}/release`)로 줄 행 단위로
회수하고, 그 회수는 사유 필수에 판단(`judgment`)을 원장에 남긴다. 보드가 지금 줄과 점유자를
레인 절로 낸다(§6). **②③④는 여전히 안 했다** — 러너도 cosign 도 도커 소켓 무인 실행도
GHE push 도 이 구현 어디에도 없고, 그 셋을 어떻게 쪼갤지는 여전히 운영자가 정한다.

## 3. 데이터 모델 — SQLite 파일 하나, 테이블 24개, 계층 셋

계층이 곧 쓰기 권한이다.

| 계층 | 무엇 | 쓰는 주체 |
|---|---|---|
| **D — 파생** | 세션·신호·발자국·ref·변경집합 | 서버(git 리더)와 러너뿐. **사람용 쓰기 엔드포인트가 없다** |
| **Q — 큐** | 항목·의존·선점·판정이력 | 사람은 `title`·`body`·`reason` 만. 나머지는 서버가 채운다 |
| **J — 판단** | 핸드오프·결정·기각·스냅숏 | 사람만. **추가 전용**(UPDATE·DELETE 트리거로 차단) |

정본은 `server/internal/store/schema.sql`. 아래는 그 요지와 **각 제약이 막는 사고**다.

**★ 24 는 세는 축을 밝혀 둔다 — 안 밝히면 다음 사람이 다른 축을 세고 어긋났다고 판단한다.**
사람이 선언한 것 = `schema.sql` 의 `CREATE TABLE` 21 + `CREATE VIRTUAL TABLE` 1(`judgment_fts`) +
증분 `002_idempotency` 의 `idempotency` 1 + 증분 `003_landing_queue` 의 `landing_queue` 1 = **24**.
반면 살아 있는 DB 에서 `sqlite_master` 를 그대로 세면 **29** 가 나온다 — FTS5 가 `judgment_fts`
하나마다 그림자 표 넷(`judgment_fts_config`·`_data`·`_docsize`·`_idx`)을 만들고, 거기에
`AUTOINCREMENT` 가 있는 표마다 공유하는 `sqlite_sequence` 하나가 더해진다(24 + 4 + 1 = 29).
다섯 다 SQLite 엔진이 만드는 부산물이라 이 절이 말하는 데이터 모델이 아니다 — 그래서 이 절은
24 를 쓴다. 실제로 다른 세션이 `sqlite_master` 값(28, 그때 `landing_queue` 전)을 "테이블 수"로
관측해 넘겨 온 적이 있다(판단 `01KZ7DKQ3QHKH75X4XY0YDPFMC`) — 두 축을 같은 이름으로 부르면
그 혼동이 반복된다.

### D 계층

- `session` — PK 는 서버 발급 ULID. **유니크 키가 `(machine_id, worktree, cc_session_id)` 3중키다.**
  워크트리 경로는 규율상 재사용된다(지우고 다시 만든다). 경로만 키로 쓰면 옛 세션 행과 합쳐진다.
  그리고 **접두 일치 코드가 존재하지 않으므로 조상 트리의 등록을 물려받는 것이 원리적으로 불가능하다.**
  그 대가는 **`worktree` 자리에 무엇이 들어오느냐가 곧 정체의 개수**라는 것이다. 훅이 날 cwd 를 보내던
  동안 대화 하나가 cwd 수만큼 행을 만들었다(실측: 행 53개 = 실제 대화 18개). 그래서 클라이언트가
  `git rev-parse --show-toplevel` 로 **트리 루트에 맞춰** 보낸다(`cmd/fd`.`resolveProject`) — 접두 일치가
  아니라 git 의 답이라 하위 디렉토리는 접히고 **서로 다른 워크트리는 여전히 갈린다.** 이 정규화가
  실패하면 fail-open 이라 옛 동작으로 떨어지고, 그렇게 생긴 중복 행은 신호를 못 받아 생존 창 밖으로
  스스로 빠진다 — 이관이 필요 없는 이유다.
  `ended` 컬럼이 없다 — 채울 수 없는 컬럼은 반드시 거짓으로 채워진다. `pid` 도 없다.
- `session_workspace` — 한 세션이 코드 레포와 문서 레포를 함께 만지는 실무를 담는다. 단수 `project` 필드로는 못 담는다.
- `signal` — 생존 "사실"이지 판정이 아니다. `kind ∈ {prompt, tool, mcp, commit, push}`.
  **PK 가 `(session_id, kind)` 라 종류별 한 행이고 갱신된다 — 횟수·간격·이력이라는 값이 없다.**
  그것들의 재료는 `event` 표뿐이다(§10). 이 문장이 여기 있는 이유는 §4 아래에 있다.
- `footprint` — 미커밋 발자국. `origin ∈ {observed, declared, claimed}` 를 **뭉개지 않는다**.
  뭉개면 "선언했으나 안 건드림"과 "선언 없이 건드림"이 구분되지 않는다.
- `ref_state` · `change_set` — **변경 시점에 계산해 불변으로 보관한다.** 브랜치가 지워져도 행이 남는다.

### Q 계층

- `item` — `landed_ref` 는 **러너가 실제로 fast-forward 한 sha 만** 들어간다.
  기존 도구가 "메인 트리의 지금 HEAD"를 적어 남의 커밋이 박히던 결함(3회 관측)이 여기서 소멸한다.
- `item_after` — `CHECK ((dep_item IS NOT NULL) + (dep_job IS NOT NULL) + (dep_sha IS NOT NULL) = 1)`.
  **브랜치 이름을 담을 컬럼이 없다.** 랜딩이 끝나면 브랜치가 지워져 조건이 충족되는 바로 그 순간
  해석 불가가 되는 결함을, 쓸 수 없게 만들어 막는다.
- `item_dependents` — 삽입 시 유지되는 역인덱스. 기존 O(n²) 전수 grep(실측 51.7초)을 O(1) 로.
- `claim` — **만료가 없다. 자동 반납이 없다. 자동 회수 코드 경로가 존재하지 않는다.**
  죽은 선점을 푸는 길은 사람뿐이다: `fd claim release --item … --reason …`(= 대시보드 회수 폼,
  같은 함수 `service.ReclaimClaim`). 실측(2026-08-07)으로 무신호 9~24.5h 세션 4곳이 12건
  (잔량의 최대 27%)을 쥔 채 아무도 못 풀었다 — 자동 만료를 되살리는 답이 아니라(생존 오판 실측
  2회) 사람의 회수 표면을 CLI 까지 늘린 것이 답이다. 회수는 judgment(decision) 하나를 남긴다.
- `pick_eval` — 추천 1건과 **탈락 사유 전부**를 기록한다. 사유 분포가 질의 가능해진다.
  `picked` 는 묶음 **선두 하나**의 항목 id 다(적격 0건이면 NULL). 나머지 구성원은 증분
  `004_pick_bundle` 이 더한 `picked_with` 에 **JSON 문자열 배열**로 가고 **선두는 거기 안 들어간다.**
  **NULL 을 빈 배열로 접지 않는다** — NULL 은 "단독이었다"이고 이 컬럼이 없던 시절의 행도 NULL 이라
  둘이 같은 뜻이다. `picked` 를 배열로 승격하지 않은 이유는 그 칸이 곧 **브랜치 이름**이고 기존 분포
  질의가 그것을 평문 id 로 읽기 때문이다. 승격하면 옛 행과 새 행이 같은 칸에서 두 형식으로 갈린다.

  **묶음 자체는 저장되지 않는다.** 표도 id 도 상태도 없다 — 저장하면 "묶음이 깨졌다"·"묶음을 해체한다"
  같은 상태 전이가 따라온다. 원장에 남는 것은 이 한 행뿐이고, 그래도 **모든 후보는 picked 이거나
  `rejected` 에 최소 한 줄**이라는 불변식이 유지된다: 적격이었는데 묶음에 못 든 항목은 `not-top`
  사유로(선두 id 와 묶음 크기를 detail 에 달고) 남고, 흡수된 항목은 `rejected` 에서 빠져 `picked_with`
  로 옮겨간다. 즉 `picked_with` 에는 **`Eligible` 이 탈락시켰던 항목이 들어올 수 있다** — 사유가 전부
  `after-unmet-item` 이고 그 선행 **전체**가 선두 하나뿐일 때만이다(같은 브랜치에서 순서대로 하면
  랜딩을 안 기다린다).

  판정 축은 셋 — 형제(한 판단이 둘을 함께 가리킨다) · 같은 선행 · 경로(선언 경로가 **정확히** 같다).
  **결합 규칙은 `(형제 ∨ 같은 선행)` 이고 경로는 보강 전용이다** — 이미 선 링크의 근거에 덧붙을 뿐
  링크를 만들지 못한다.
  **★ 이 규칙은 실측이 초안을 뒤집은 결과다.** 겹침 판정(`PathsOverlap`)은 조상 디렉토리도 겹침으로
  세는데 그 규칙은 "남과 부딪히나"에는 옳다. 그대로 묶음에 쓰면 무너진다 — `cmd/fd` 를 **디렉토리 통째로**
  선언한 항목 하나가 열린 16건 중 **10건**을 한 묶음으로 끌어왔고, 이 문서처럼 모두가 한 줄씩 고치는
  파일 하나로 4건이 서로 묶였다. **파일을 공유한다는 사실은 함께 할 이유가 못 된다.** 그래서 별도
  술어(`judge.SamePaths`)로 정확 일치만 센다 — 같은 함수를 두 질문에 쓰면 한쪽을 고칠 때 다른 쪽이
  조용히 바뀐다.

  정렬 키는 넷이고 **조정할 상수가 0개다**: ① 의존자 수 합 ↓ · ② 묶음 크기 ↓ · ③ 최고령 구성원 ↑ ·
  ④ 선두 id 사전순.
  **★ ②가 없으면 이 기능이 발화하지 않는다** — 열린 16건 전부 의존자 0이라 ①이 상수이고, 그러면 ③이
  실질 1차 키가 되는데 그 최고령 항목은 교정된 규칙에서 **단독**이었다. ④는 동점 처리가 아니라 실제로
  브랜치 이름을 정한다(생성 시각이 마이크로초까지 같은 형제 셋은 ①②③이 전부 동점이다). 그래서 네 키의
  **실제 값**을 응답의 묶음 사유에 그대로 싣는다 — 답 못 하는 자동 선택은 두 번째 세션부터 무시된다.

### J 계층

- `judgment` — 추가 전용. `BEFORE UPDATE`·`BEFORE DELETE` 트리거가 `RAISE(ABORT)` 한다.
  정정은 새 행 + `supersedes`. **남의 절을 덮어써 원문이 영구 소실된 사고(2회)가 물리적으로 불가능해진다.**
- `judgment_link` — 판단 ↔ 항목·잡·커밋의 FK. 경로 문자열 포인터가 FK 가 되면 끊긴 포인터가 원리적으로 사라진다.
- `snapshot` — 비싼 전수 판정의 결과처럼 재계산이 불가능한 수치.
  `CHECK (method <> 'manual' OR evidence IS NOT NULL)` — **"손으로 올리지 마라"는 규율이 제약이 된다.**
  `input_digest` 를 함께 저장해 현재 트리와 다르면 UI 가 자동으로 "낡음"을 붙인다. **"낡았다"가 파생이 된다.**

### 설정·자원

- `project` — `path`·`remote_url`·`default_branch`. 나머지 설정은 레포 안의 커밋된 `.flightdeck.yaml` 이 정본이고 DB 는 캐시다.
- `counter` — **원자적 발번기.** 락이 원리적으로 못 지키는 논리 카운터(개정 차수·스키마 버전)를 여기서 닫는다.
- `resource_hold` — `CREATE UNIQUE INDEX … WHERE released_at IS NULL`.
  **배타를 애플리케이션 판정이 아니라 DB 제약으로 만든다.** 판정을 앱에서 빼면 우회할 코드도 없다.
- `event` — 추가 전용 감사·계측 원장. 반납이 `rm -rf` 로 흔적을 지우던 구조가 사라진다.

## 4. 생존 — 판정 기구를 만들지 않는 것이 답이다

불리언을 만드는 순간 그것이 회수·회피·탈락 셋의 상류가 된다. 그 판정은 실측에서 두 번 틀렸다 —
죽었다고 판정한 세션이 그 뒤 6커밋을 랜딩했고, 419분 무갱신으로 표시된 세션이 실제로는 17초 전에 살아 있었다.

**신호 넷을 나란히 낸다. 합치지 않는다.**

| kind | 발생 | 뜻 |
|---|---|---|
| `prompt` | `UserPromptSubmit` | 사람이 지금 몰고 있다 — 가장 강한 신호 |
| `tool` | `PostToolUse(Edit\|Write)` | 에이전트가 일하고 있다(사람이 자리를 비워도) |
| `mcp` | MCP 도구 호출 · 판단 저장(`fd note`·PreCompact 훅 포함) | 세션이 살아 있다 — 일하고 있다는 뜻은 아니다 |
| `commit`·`push` | 서버의 git 리더가 직접 관측 | **클라이언트를 안 믿는 유일한 신호** |

**이 표는 종류마다 정확히 한 행이고 갱신된다.** 답할 수 있는 것은 "이 세션의 이 종류 최신 신호 시각"
하나뿐이다 — 횟수·간격·분포·과거 시점은 `event` 표에서만 나온다(§10). 표가 kind 를 행으로 늘어놓은
모양이 "행이 쌓인다"로 읽히는데, 실제로 쌓이는 것은 `event` 다. 이것을 안 적어 둔 탓에 큐 항목 둘이
잴 수 없는 것을 재라고 지시했고, 집은 세션이 벽에 부딪혔다 — 관문은 `store/signal_is_not_history_test.go` 다.

`prompt` 와 `tool` 을 가르는 이유: 에이전트가 20분짜리 도구를 돌리는 동안 `prompt` 는 안 오지만 `tool` 은 온다.
반대로 사람이 읽기만 하는 동안은 `prompt` 만 온다. **하나만 보면 둘 중 한 상황을 반드시 오판한다.**

- **"죽었다"고 쓰지 않는다.** 나이를 숫자로만 낸다.
- **무갱신 경고를 상시 점등시키지 않는다.** 지금 기존 도구는 살아 있는 5건 중 3건에 경고가 붙어 판별력이 0이다.
  임계 알람은 세션이 아니라 **자원**(디스크·레인)에만 붙인다.
- 상태 중 `active` 는 파생이고, `paused`·`blocked`·`done` 은 사람이 쓴다(관측으로 구분 불가하므로). **`blocked` 에는 사유가 필수다.**

### 세션은 어떻게 닫히나 — 그리고 무엇이 안 닫히나

`done` 이 되는 경로는 둘이다. **둘 다 관측이지 판정이 아니다** — 무응답·나이·pid 에서 죽음을
추론하는 자리는 이 도구 어디에도 없다.

- `fd close` / `fd finish --close` — 사람이 "끝났다"고 말한 것
- `SessionEnd` 훅(matcher `clear`) — /clear 로 그 대화가 떠난 것(§6)

**닫는 것은 되돌릴 수 있다.** `Tx.OpenSession` 은 닫힌 카드를 다시 열면 `active` 로 되살린다.
그래서 /clear 직후 rekey 로 이어진 카드가 done 인 채 사라지지 않는다. 훅 넷 중 셋(`SessionStart`·
`UserPromptSubmit`·`PostToolUse`)과 MCP 도구 호출이 전부 그 자리를 지나므로, **사람이 말을 걸거나
도구를 쓰는 순간 카드가 살아난다.** `blocked` 는 안 건드린다 — 사람이 사유와 함께 남긴 판단이라
여는 것이 조용히 지우면 안 된다.

**선점을 든 세션은 어느 경로로도 안 닫힌다.** 닫힌 카드는 `ListLive` 에서 빠지고, 그러면 그 선점이
아무에게도 안 보인다 — 항목을 아무도 못 집는데 누가 잡았는지도 안 보이는 상태가 된다.

**★ 안 닫히는 것을 반드시 알아야 한다.** 창을 닫고 나간 세션·`tmux kill`·SIGKILL 은 이 경로를
안 지난다(플랫폼이 프로세스 종료를 안 알려 준다 — §6·§13). 그 카드는 여전히 창(기본 2시간)으로만
사라진다. 실측 하나: 2026-08-05 context-platform 보드가 카드 26장을 냈을 때 `/proc` 으로 잰 살아
있는 claude 프로세스는 5개였고, 그중 16장은 신호가 열림 하나뿐(발자국 0)이었다
(**당시 판**: 세션 열기가 `mcp` 를 찍었다. 그 자리는 지웠으므로 지금 그 카드는 신호가 0건이다).

이 한계를 안 적으면 다음 사람은 "닫히니까 카드는 항상 정확하다"고 믿는다. 그 믿음이 회수·회피
판단의 상류가 되면 위의 두 오판이 다시 난다.

**회수는 사람만, 사유 필수, 그리고 근거를 다섯 축으로 나란히 보여준 뒤에.**
마지막 신호 종류·나이 · 발자국 경로 수 · 원격 마지막 커밋 시각 · 미푸시 커밋 수 · 마지막 판단.
**하나의 신호로 판정하지 않는다** — 두 번의 오판이 둘 다 근거가 하나뿐이라 났다.

회수 행위 자체가 `judgment(kind='decision')` 으로 추가 전용 기록된다.

## 5. 파생 — 무엇이 손 기재에서 사라지는가

이 표가 곧 "쓰기 API 에서 삭제된 필드" 목록이다.

| 지금 손으로 적는 것 | 파생 원천 |
|---|---|
| 세션의 `branch`·`head`·`worktree`·`updated` | `ref_state` + 신호 |
| 세션 상태(active/landing/done) | 신호 + 잡 |
| 큐 항목의 랜딩 sha | 러너가 실제로 ff 한 sha |
| 큐 의존 충족 여부 | `merge-base --is-ancestor`, 종료코드 0/1/128 **세 값을 가른다**(오타와 "아직"을 뭉개지 않는다) |
| 큐 경로 겹침 | `footprint` ∪ `change_set` |
| 핸드오프의 랜딩 sha·검증 통과 줄 | 잡 레코드 |
| 핸드오프의 후속 항목 id | `judgment_link` FK |
| 대시보드 전체 | 위 전부의 뷰 |

### 경로 겹침 축 — 세 겹을 다 고친다

1. **정규화 결함 제거.** 경로를 성분 단위로 비교한다. 시험 표는 실측 반례 그대로다 —
   `a.toml` vs `a.toml` → 겹침 · `tools/` vs `tools/x.sh` → 겹침 · `tool/` vs `tools/` → 안 겹침.
2. **프로젝트가 N개라 레포 축 오탐이 자연히 사라진다.**
3. **착수 구간을 `footprint` 가 덮는다.** 브랜치 diff 는 규율을 지킨 세션에 정의상 비어 있다.

**그리고 거르지 않고 알린다.** `pick` 이 `이 항목의 경로가 세션 X 와 겹친다(거르지 않음)` 을 명시한다.
침묵하면 "겹침 없음"과 "이 축을 안 본다"가 구분되지 않는다.

`track` 은 `label` 로 개명하고 **어떤 배제 판정에도 쓰지 않는다.** 자유 문자열이라 절반 이상이 디렉토리 경계가 아니다.

### 남는 손 기재 넷 — 원리적으로 파생 불가

| 남는 것 | 왜 |
|---|---|
| `judgment(kind=handoff)` | 왜 그렇게 했나 · 무엇을 기각했나 · **일부러 안 한 것** · 확인했으나 못 한 것. 안 남기면 다음 세션이 **의도적으로 남긴 자리를 결함으로 보고 고치러 간다** |
| `note(kind=ask)` | 남이 건드리면 곤란한 것. **커밋 전 의도를 나르는 유일한 축** |
| 서사(랜딩이 무엇을 바꿨나 · 무엇이 막혔나) | git log 는 무엇을 고쳤는지 알지만 무엇이 달라졌는지는 모른다 |
| `snapshot` | 비싼 전수 판정 결과. 신선도만 파생으로 붙인다 |

### 그래도 안 보이는 것 넷 — 메우지 않고 명시한다

1. **커밋도 편집도 안 하는 세션**(조사·판정만). `board` 가 `발자국 없음 (prompt 3분 전)` 으로 표시한다.
   그 세션은 경로 축에서 아무도 안 막고, **안 막는다는 사실이 화면에 있다.**
2. **브랜치 이름 충돌** — `pick` 이 브랜치 이름으로 항목 id(PK)를 발급한다. 전역 유일이라 구조적으로 소멸한다.
3. **원격 도달성** — `fd doctor` 가 머신마다 잰다. Tier A 는 도달성이 필요 없다(로컬 git).
4. **의미 표류**(충돌 난 줄이 아니라 다른 줄이 낡는 것) — **자동으로 못 잡는다.** 셋으로 나눠 부분 처리한다:
   논리 카운터는 발번기가 원천 차단(Tier A) · 랜딩 커밋의 변경 경로를 겹치는 선점에 배달(Tier B) · 재실행 단정(Tier C).
   **한계를 숨기지 않는다** — 읽지도 고치지도 않은 자리의 표류는 못 잡고, 대시보드가 커버리지를 표시한다.

## 6. 표면

### MCP 도구 7개

전체 이름은 `mcp__plugin_flightdeck_fd__<도구>` 다.

| 도구 | 인자 | 반환 |
|---|---|---|
| `board` | `detail?` | 살아 있는 세션 표 + 각자의 마지막 신호 종류·나이 + 지금 만지는 경로 + 미확인 결과. 기본 1,200토큰 |
| `pick` | `item_id?`, `item_ids?`, `steal_reason?` | 인자 없으면 **함께 갈 항목까지 묶어** 추천 + 왜 + **탈락 사유 전부**(묶을 게 없으면 단독이라 말한다). `item_ids` 를 주면 묶음으로 선점한다 — **첫째가 선두**이고 그 id 가 브랜치다, 선두는 **원자**(못 집으면 아무것도 안 씀)이고 나머지는 되는 대로 집어 **못 집은 사유**를 낸다 — + 항목 본문 + 연결된 판단 전문 + 워크트리 준비 명령. `item_id` 하나만 주면 단건 그대로다(`item_id`·`item_ids` 동시 지정은 거절). **이미 자기 것이면 맥락 재출력**(재개 경로). 어느 쪽이든 **남은 큐 열림 수**가 함께 온다 — 서버 판이 그 축을 안 내거나 세지 못했으면 숫자 대신 **그 사실**이 온다 |
| `note` | `kind`, `body`, `item_id?` | 저장 확인 + 이 노트를 받을 세션 수 |
| `add` | `id`, `title`, `body`, `paths?`, `after?` | 생성 확인 |
| `finish` | `item_id`, `outcome`, `body`, `followups?[]` | **한 호출이 판단 저장 + 후속 등록(이미 있는 id 면 잇기) + 종료 + 워크스페이스 해제를 원자적으로** |
| `alloc` | `counter_name` | 다음 정수 |
| `land` | `result?`, `detail?`, `leave?`, `release?` | 인자 없으면 랜딩 레인 줄에 서거나(재진입 안전) 내 차례를 재확인 — `turn`\|`waiting`(앞사람·순번)\|`reclaimed`(회수 사유). `result` 로 다 쓰고 보고+반납(`ok`\|`fail`), `leave` 로 줄에서 이탈. `release` 는 **이 서버가 거절한다**(레인 회수는 사람만, §4) |

**도구 수를 예산 안에 묶는 이유는 컨텍스트다.** 세션 시작에는 도구 이름과 서버 instructions 만 실리고,
스킬 목록은 컨텍스트의 1%·항목당 1,536자에서 절단되며 덜 쓰는 것부터 버려진다(**측정 전
잠정이다** — §13 「아직 아님」 6. 절단되는 것이 `description` 인지 본문까지인지도 그 줄에 있다).
**그래서 규율 산문을 도구 설명이나 스킬에 넣지 않는다.** 6개에서 7개(`land`)로 늘어난 것은 이 예산을
안 건드린다 — 늘어난 것은 세션 시작 목록에 실리는 고정비, 즉 도구 **이름** 하나뿐이고, 그 설명도
도구별 90자 상한(`mcpsrv/protocol_test.go` 의 `TestToolTableIsSeven`)을 그대로 지킨다.
`land` 가 나르는 규율(레인 상태 다섯 갈래·회수 거절 사유)은 스킬이나 도구 설명이 아니라 그 도구의
**응답**(`RenderLand`)에만 있다 — 다른 여섯이 이미 그렇듯, 여기서도 규율은 필요할 때 그 자리에서만 실린다.
서버 instructions 는 300자 고정:

> 작업은 `pick`, 판단은 `note`, 끝나면 `finish`. 락은 없다.
> head·branch·sha·랜딩 이력은 서버가 git 에서 읽으므로 적지 마라.
> 겹침·선점·미확인 결과는 응답 꼬리에 온다.

**규율은 응답에 싣는다 — 필요할 때만, 그 자리에서.**
`finish` 를 `body` 없이 부르면 무엇을 적어야 하는지를 그 자리에서 낸다.
`pick` 꼬리에 브랜치·워크트리 명령이 온다. 모든 응답 꼬리에 미확인 알림이 온다.

**`POST /footprints` 는 이 표에서 지웠다(2026-08-05, 실제로 코드에서 제거).**
신호 없이 발자국만 남기는 표면이었고 `origin=declared|claimed` 를 받을 수 있어
`Beat`(observed 고정)와 표현력이 달랐다. 지운 근거는 그 차이가 **쓰이는 자리가
없다**는 실측 셋이다 — 비시험 클라이언트 0건, `origin=declared` 행 **0건**(observed
592 · claimed 140), 그리고 `claimed` 는 `service.Pick` 이 선점 트랜잭션에서 직접
넣는다. 즉 차이는 실재했으나 그 차이가 만든 데이터가 한 행도 없었다.
발자국이 들어오는 문은 이제 **둘**이고(`service.Beat`·`service.Pick`) 그 개수는
`service.TestFootprintDoorsAreExactlyTwo` 가 전수로 잠근다.

**`POST /sessions/{id}/workspaces` 는 클라이언트가 0건이지만 남긴다.**
같은 "호출자 없음"인데 결론이 갈리는 기준은 **대체재**다 — 발자국은 위 두 문으로
들어오지만, 부(副) 워크스페이스를 넣을 문은 이것 하나뿐이다. 다만 지금 이 표에는
세션 행이 이미 갖고 있지 않은 값이 **한 건도** 없다(2026-08-05 재측정: 126행 ·
non_primary 0 · `session.worktree` 와 다른 값 0). **이 표를 근거로 세션 키에서
worktree 축을 빼면 그 축은 아무 데서도 복구되지 않는다** — 근거 전문은
`store/session.go` 의 `AddWorkspace` 주석에 있다.

**`/notices` 는 응답 꼬리(미확인 알림) 전용이고 세션 카드 파생을 돌지 않는다.**
꼬리는 MCP 응답 **전부**에 붙으므로, 그 값을 `/dashboard.json` 에서 가져오면
도구 호출 1회마다 `git worktree list` + 세션마다 `ChangedPaths`·`UncommittedPaths` 가
한 번 더 돈다 — 지금은 8~60ms 라 무해하지만 세션·워크트리가 늘면
**모든 도구 응답 지연에 저장소 전수 훑기가 얹힌다.** 표면을 가르면 그 비용이
`/metrics` 의 라우트 라벨에서도 화면 트래픽과 갈려 보인다.

인증은 `Authorization: Bearer <token>`. 사용자 1명이므로 토큰 1개, 역할 없음.
**루프백은 토큰 없이 허용하되, `/healthz` 는 그 면제가 실제로 닿는지를 알린다.**
`loopback_configured` 가 설정값이고, `loopback_open` 은 설정이 열린 채 루프백 요청이
이 프로세스에 한 번이라도 닿았을 때만 참이다 — 안 닿는 사유는 `notice` 가 말한다.
컨테이너로 띄우면 호스트 요청이 브리지 게이트웨이로 보여 면제가 구조적으로 안 걸린다.
도달은 API 요청만 남긴다 — `/healthz` 는 게이트 앞이라 안 센다(컨테이너 헬스체크가 그 창을 30초마다 친다).
모든 쓰기에 `Idempotency-Key: <session>:<seq>`.

**`/healthz` 의 `self_update` 는 서버가 자기 교체를 따라가고 있는가다**(축 자체는 §7).
모양은 `internal/api/handlers_meta.go` 의 `SelfUpdateStatus` 가 정본이다. 읽는 순서에 규율이 있다 —
**`watching` 이 먼저**이고, 거짓이면 `reason` 이 왜 안 보는지를 말한다. 그 둘을 접으면 "아직 갱신이
없었다"와 "안 보고 있다"가 같은 빈칸으로 보인다. **성공은 여기 안 남는다**: 성공하면 프로세스가
갈아치워져 새 프로세스는 그 사실을 모르고, 남는 것은 빌드 좌표가 바뀐 것뿐이다 — 그래서 `outcome` 은
`refused`·`failed` 둘뿐이다. `stalled` 는 **보고는 있는데 지금 실행 파일을 못 잰다**는 별개 사실이라
`outcome` 으로 접지 않는다. 접으면 지워진 바이너리를 감시하는 서버가 화면에서 정상으로 보인다.

### 훅 6종 — 전부 fail-open, 전부 `${CLAUDE_PLUGIN_ROOT}/bin/fd` 절대경로

| 이벤트 | matcher | 하는 일 |
|---|---|---|
| `SessionStart` | `startup\|resume\|clear\|compact` | `fd session open` → `additionalContext` 에 보드 요약 + 내 선점 + 미확인 결과 + **서버 상태 배너** |
| `UserPromptSubmit` | — | `fd beat --kind prompt` (2초 타임아웃) + 미확인 알림 주입 |
| `PostToolUse` | `Edit\|Write` | `async` `fd beat --kind tool --path <file>` — **미커밋 발자국의 유일한 원천** |
| `PreCompact` | — | `async` `fd note --draft` — 압축으로 판단이 날아가는 것만 막는다 |
| `Stop` | — | `fd hook stop` → 처방(발화 5조건, 전이 1회) 주입. **fail-open, 3초** |
| `SessionEnd` | `clear` | `async` `fd hook session-end` → 떠나는 대화의 카드를 닫는다. **선점이 있으면 안 닫는다** |

## 7. 열화 — 등급 둘

**L0 — 서버 도달.** 전부 동작.

**L1 — 서버 미도달.** `SessionStart` 가 `additionalContext` 로 **명시 주입**한다.
조용히 두면 에이전트가 조정 기구가 있는 줄 알고 움직인다.

```
⚠ 조정 서버 미도달(http://localhost:7420, 마지막 접속 14:02 · 37분 전).
  되는 것: 코드 작성·커밋·조사 전부. 이미 선점한 항목의 작업.
  안 되는 것: 새 항목 선점 · 다른 세션의 현재 상태.
  아래는 14:02 시점의 스냅숏이다. 그 뒤 남이 무엇을 집었는지는 알 수 없다.
```

- **읽기**: 마지막 성공 응답을 **"낡음: 37분 전" 배너와 함께** 반환한다. 침묵하지 않는다.
- **쓰기**: `judgment`·`note` 만 아웃박스에 쌓이고 재연결 시 멱등 재생.
  **선점은 오프라인에서 안 된다** — 배타는 서버만 보장할 수 있고, 오프라인 획득을 허용하면 배타가 거짓이 된다.
- 상태를 두는 자리는 **두 축**으로 가른다: ① **재생성 가능한가** ② **갈린 사본이 각자 옳은가**.
  둘 다 "예"여야 채널 사다리(`StateDir`)에 남는다.
  **왜 축이 둘인가.** 하나(①)로는 이 규칙의 **첫째 적용인 `machine-id` 를 설명하지 못한다** —
  그것은 `crypto/rand` 로 만드는 **완전히 재생성 가능한** 값인데도 고정 자리로 갔다. env.go 가
  거기서 실제로 쓴 축은 "같은 머신이면 같은 값인가" = ②였다. 그 이름을 여기서 정식화한다.
  - **응답 캐시** — `${CLAUDE_PLUGIN_DATA}` 아래(`${CLAUDE_PLUGIN_ROOT}` 는 업데이트마다 경로가 바뀐다).
    채널마다 갈려도 된다. 잃어도 다시 만들면 된다(①통과).
    **갈려도 되는 근거는 ②다** — `CacheEntry` 가 **자기 시각을 값에 달고 다니고** 읽기가
    "낡음: 37분 전" 배너로 그것을 말한다. 두 채널의 사본이 달라도 **각자 자기 시점의 참**이라
    거짓말을 하는 사본이 없다.
  - **바이너리 캐시** — `~/.cache/flightdeck/bin/fd-<소스 트리>`,
    **채널 환경과 무관한 고정 자리 + 소스 지문**(`FD_STATE_DIR` 만 예외).
    재생성은 가능하지만(①통과) **②에서 탈락한다** — exec 되고 나면 자기가 어느 판인지
    **안 말하고 답한다.** 두 벌이 다르면 하나는 **최신인 척하는 옛 코드**다.
    2026-08-06 실측: 두 자리의 빌드 시각이 55분 어긋난 창(16:10:44 ↔ 17:05:29)에서
    **한 응답의 서버 축과 렌더 축이 서로 다른 판을 봤다.**
    **이름에 소스를 박는 이유**는 재빌드 판정이 mtime 이라 한 이름을 여러 소스가 나눠 쓰면
    **먼저 지은 쪽이 전 채널을 대표하기** 때문이다(실험으로 재현했다 — 워크트리에서 런처를
    한 번 부르는 것만으로 모든 세션의 훅·MCP 가 그 브랜치 빌드로 갈아 끼워진다).
    지문은 ②의 배신이 아니라 형식화다: 채널 분기는 **같은 입력이 다른 출력**을 내는 것이고
    (주소에 안 적힌다), 소스 분기는 **다른 입력이 다른 출력**을 내는 것이다(주소에 적혀 있다).
    ②가 금지하는 것은 전자뿐이다.
    **지문에는 값이 있다 — 서버 자기 갱신의 트리거 하나를 못 쓰게 만든다.** 판정은 아래
    「서버는 자기 실행 파일 교체를 감지해 스스로 재기동한다」에 산다(여기서 되풀이하지 않는다).
    **`~/.flightdeck` 이 아닌 이유**: 그 자리는 `compose.yaml` 이 컨테이너에 `/data` 로
    **쓰기 가능**하게 물리고 재생성 불가한 `fd.db` 와 판단 백업이 산다. 거기 실행 파일을 두면
    네트워크에 열린 컨테이너가 **호스트가 exec 하는 파일**을 쓸 수 있게 되고, 백업이 22MB×N 을
    함께 뜬다. 보호막은 **물려받는 것이 아니라 짓는다** — 런처가 그 `mkdir` 을 `umask 077`
    서브셸에서 돌려 **새로 만드는** 자리를 0700 으로 둔다(이미 있는 자리는 안 건드린다).
    앞선 판은 "`~/.cache` 는 0700 이라(실측) 보호막이 따라온다"고 적었는데 **그 근거는 갈래를
    안 셌다**: 0700 은 이 머신에 **이미 있던** 디렉토리의 성질이지 자리의 성질이 아니다.
    `~/.cache` 가 없는 머신(새 컨테이너 이미지·CI 러너·갓 만든 계정)에서는 런처가 그 디렉토리의
    첫 생성자이고, 맨 `mkdir -p` 는 ambient umask 를 타 002 아래 **0775** 가 된다 — 거절한
    `~/.flightdeck`(Go 가 0755 로 짓는다)보다 **오히려 넓다**(실측으로 재현). 모드 판정의
    주인은 런처의 `mkdir` 하나다(bin/fd) — env.go 의 `BinCacheDir` 은 자리만 답한다.
    **HOME 이 없으면 안 짓는다** — world-writable 한 `/tmp` 에 실행 파일을 놓는 것은
    남이 심어 둔 것을 내가 exec 하는 길이다.
    **옛 자리는 이관하지 않는다** — 재빌드가 런처의 정상 경로라(웜 0.49초) 잃는 것이 **0**이고,
    복사하면 mtime 이 따라와 **필요한 재빌드를 억제한다.** 그 값은 **디스크로** 치른다.
    ★ **그 잔존은 이제 doctor 가 센다 — 앞선 판이 "정직한 구멍"으로 접어 둔 자리다.**
    화면에 **두 줄이 나란히 살고, 겹쳐도 된다** — 축이 다르기 때문이다. "이 실행 파일은
    **런처가 짓는 자리 밖**이다" 줄은 **지금 도는 프로세스**를 재고(exe.go 가 자기 머리에서
    그렇게 적었다), 옛 자리에서 이미 exec 된 프로세스가 살아 있는 **이행 창 동안만** 뜨며
    세션이 한 번 재기동하면 사라진다. 그 뒤 옛 자리에 남는 **파일**은 이제
    `  ! 옛 바이너리 자리 %s — fd %d개 · %s(아무도 안 쓴다. 지우려면 사람이 지운다)` 가 잰다
    (cmds.go 의 `legacyBinLeftovers`, 후보 목록은 env.go 의 `LegacyBinDirs`). 셀 수 없으면
    `  ! 옛 바이너리 자리 %s — 세다 걸렸다: %s` 로 **갈라** 낸다 — 0개와 '못 쟀다'를 가른다
    (침묵은 '깨끗하다'로 읽힌다). 자리가 없거나 파일이 0개면 **한 줄도 안 낸다**: 「0건」 줄은
    몇 달에 한 번 참인 축을 매 실행마다 뜨는 잡음으로 만들고, 잡음이 된 줄은 정작 참인 날
    아무도 안 읽는다. 둘을 하나로 접으면 세션이 한 번 재기동한 뒤 44MB 가 다시 안 보이게 되고,
    **그 침묵이 이 항목이었다**(2026-08-07 재실측: `~/.local/state/flightdeck/bin/fd`
    22,144,360 바이트 + `${CLAUDE_PLUGIN_DATA}/flightdeck/bin/fd` 22,049,451 바이트 =
    **44.2MB**. 앞선 판이 적은 `43MB` 는 그 둘을 더한 값이 아니었다 — 파일별 숫자는 그대로
    옳다. 문서와 화면이 같은 자를 쓰도록 `humanBytes` 가 10^6 기준이고 단위를 이름으로 적는다.
    `du -h` 는 2^20 이라 같은 파일을 `21M` 로 낸다).
    **지우지는 않는다 — 이관 안 함 판정도 그대로다.** doctor 는 말만 하고, `PruneBinCache` 는
    여전히 지금 자리 한 디렉토리만 훑는다. 지우는 한 줄은 README 에 있다.
    **되돌리기도 대칭이 아니다**: `git revert` 는 런처를 사다리로 되돌리면서 GC(`PruneBinCache`)를
    함께 지우므로 `~/.cache/flightdeck/bin` 에 남은 최대 keep(3)벌 ≈66MB 이 주인을 잃는다.
    그 한 줄도 README 의 같은 자리에 있다.
    ★ **접두는 둘이고 합치면 안 된다.** GC 의 `binCachePrefix`(`"fd-"`, bincache.go)는 **안
    지울 것**을 넓히는 배제 조건이라 좁을수록 안전하고, 진단의 `legacyBinPrefix`(`"fd"`,
    cmds.go)는 **말할 것**을 넓히는 포함 조건이라 좁으면 침묵한다. 옛 런처가 짓던 이름에는
    접두가 없어서(`fd`), `fd-` 로 세면 이 줄이 존재하는 이유인 그 두 파일이 정확히 **0개**로
    세어진다.
    ★ **앞선 판이 "안 메운 이유"로 적은 문장은 틀렸다 — 옛 사다리를 Go 에 두는 것은 자리의
    주인을 하나로 모은 일을 안 되돌린다.** 사본이 되는 것은 *같은 질문에* 두 번 답할 때인데
    두 질문이 다르다: `BinCacheDir` 은 "지금 어디에 짓나", `LegacyBinDirs` 는 "예전에 어디에
    지었나". 증거는 **동기화 방향**이다 — 자리가 또 옮겨지는 날 사본이라면 따라가야 하지만
    이 목록은 옛 항목을 **그대로 들고 있어야** 한다. `LegacyOutboxDirs` 가 `OutboxPath` 에 대해
    갖는 관계와 같고, 그래서 새 규칙이 아니다. 그 성질이 **조립 규칙까지 가른다**: 옛 사다리
    (`CLAUDE_PLUGIN_DATA`·`XDG_STATE_HOME`·`~/.local/state`)는 **얼어붙은 과거**라 코드에 박고,
    넷째 후보인 고정 자리는 과거가 아니라 **지금 자리의 형제**라 주인에게 묻는다
    (`BinCacheDir(envWithout(get, "FD_STATE_DIR"), home)`). 그 넷째가 있는 이유는 `FD_STATE_DIR`
    를 **새로 켠** 사용자에게 `~/.cache/flightdeck/bin` 이 통째로 버려지고 GC 도 더는 안 훑어
    keep(3)벌 ≈66MB 이 주인을 잃기 때문이다. 베끼면 그때야말로 사본이다.
    ★ **이 목록은 `MachineIDPath` 가 거절한 "채택 순서가 채널마다 갈린다"에 안 걸린다.**
    그 결함은 목록에서 **하나를 골라 답으로 삼을 때** 선다 — 채널마다 목록이 다르니 고른 것도
    달라져 한 머신이 정체를 둘 갖는다. 여기는 **아무것도 안 고른다**: 후보를 다 찍고, 못 보는
    자리에는 침묵한다. 채널마다 줄이 달라지는 것은 상태의 갈림이 아니라 **시야의 차이**이고,
    축 ②로 말하면 갈린 두 보고가 **각자 제 시점의 참**이라 응답 캐시와 같은 자리에 선다.
    그 시야를 화면이 스스로 적는다 — 「옛 자리 탐색(아웃박스 큐 · 바이너리 자리)은 이 채널이
    계산할 수 있는 자리만이다 — 다른 채널(훅·MCP 는 CLAUDE_PLUGIN_DATA)의 자리는 여기서 안
    보인다.」(2026-08-07 실측: 사용자 셸에는 `CLAUDE_PLUGIN_DATA` 가 안 걸려 있어 위 두 파일 중
    **한 줄만** 떴다.)
    ★ **"읽기 전용 진단이라 채널 후보를 훑어도 된다"는 이 축의 논거가 아니다.** 읽기 전용은
    목록이 틀렸을 때 치르는 *값*을 낮출 뿐('남의 판단을 사용자 이름으로 전송'이 아니라 '거짓 줄
    하나') 채택이 갈리는 *기구*를 없애지 않는다. 그 축의 답은 위의 "아무것도 안 고른다"다.
    읽기 전용이 실제로 답하는 것은 **임시 디렉토리**뿐이고 거기서도 절반만 답한다 — 옛 런처의
    `${HOME:-/tmp}` 폴백이 `/tmp/.local/state/flightdeck/bin` 을 실제로 지을 수 있었지만 후보에
    **안 넣었다**: 이 줄이 읽기만 해도 나르는 처방은 **사람의 `rm`** 이고, `/tmp` 는 부모가
    world-writable 이라 남이 그 경로를 먼저 만들 수 있다(개수·크기도 심은 쪽이 정한다). 얻는
    것은 가설이고(이 제품의 채널 셋은 전부 HOME 이 있다) 잃는 것은 구체적이다. 환경변수에서
    우연히 온 tmp 는 안 거른다 — 그 축은 사용자 자신의 프로세스만 세팅한다.
    (기록 전문과 실측은 env.go 의 `LegacyBinDirs` ★ 에 있다. 여기는 설계 판정만 둔다.)
    ★ **이 항목만은 §7 의 침묵이 아니라 §7 의 문장을 뒤집는다.** 앞선 셋
    (`machine-id`·`config.json`·아웃박스)은 이 절이 **안 말한 것**을 정했지만, 바이너리 캐시는
    이 절이 「캐시 — `${CLAUDE_PLUGIN_DATA}` 아래」로 **명시 허가한 것**을 회수한다.
    회수하는 근거는 그 허가의 논거("경로가 바뀌면 쌓아 둔 캐시가 갱신 한 번에 사라진다")가
    **재빌드 판정이 있는 바이너리에는 안 서기** 때문이다 — 플러그인 설치가 소스 mtime 을
    설치 시각으로 찍어 릴리스마다 어차피 재빌드다. 응답 캐시에는 그 논거가 **그대로 서고**,
    그래서 응답 캐시는 안 옮긴다.
  - **아웃박스·격리** — `~/.flightdeck/outbox`, **채널 환경과 무관한 고정 자리**.
    상태 디렉토리는 훅·MCP(`CLAUDE_PLUGIN_DATA`)와 사용자 셸(`XDG_STATE_HOME`)로 갈리는데,
    거기 두면 **셸에서 쌓인 판단을 훅·MCP 가 영영 못 보낸다**(2026-08-03 실측: 판단 하나가
    그렇게 갇혔다). `machine-id`·`config.json` 이 이미 같은 이유로 같은 자리에 있다.
    옛 자리에 남은 큐는 **옮기지 않는다** — 재생이 제자리에서 돌려 전송으로 비운다.
    옮기려면 "읽고·쓰고·원본을 치운다"는 세 단계를 원자화해야 하는데 `os.Rename` 하나로는
    그것이 안 된다(이 자리에서 한 번 틀렸다가 재현으로 뒤집혔다).

**"고정 자리"는 이제 두 뿌리를 가리킨다** — 판단·정체(아웃박스·`machine-id`·`config.json`·비콘)는
`~/.flightdeck`, 재생성 가능한 바이너리는 `~/.cache/flightdeck`. **채널 무관이라는 성질은 둘이 같다.
다만 뿌리를 가른 것은 각 항목의 ① 판정이 아니다** — `machine-id` 도 비콘도 ①을 통과하고서
`~/.flightdeck` 에 산다(`window/dir.go` 가 같은 사다리를 같은 이유로 쓴다). 가른 것은 **그 자리에
사는 자산의 등급과 산출물의 부피**다: 재생성 불가한 20MB 짜리 DB 와 판단 백업 옆에 22MB×N 짜리
언제든 다시 지을 수 있는 것을 쌓지 않는다. 이 분기를 여기 적어 두는 이유는, 안 적으면
다음 사람이 "왜 넷째만 딴 데 있나"를 처음부터 다시 판정하러 오기 때문이다.

**아웃박스를 판단·노트로만 좁힌 이유**: 그것이 재생성 불가한 유일한 자산이다.
잃어도 다시 만들면 되는 것에 재생 기구를 만들지 않는다.

**`finish` 는 오프라인에서 거절한다 — 아웃박스에 안 쌓는다.** 이 도구는 한 호출이
판단 저장 + 후속 등록 + 항목 종료 + 워크스페이스 해제를 **원자적으로** 하는 것이 존재 이유다(§6).
아웃박스는 요청 하나를 나중에 다시 보내는 기구라 그 원자성을 보장하지 못한다 —
재생 시점에 항목 상태가 이미 달라져 있으면 판단만 남고 종료는 실패하는 반쪽이 생기고,
그때 원장에 "끝냈다는 판단"과 "안 끝난 항목"이 함께 남는다. **그것이 이 제품이 없애려는 표류의 정확한 모양이다.**
그래서 거절하고, 판단만 따로 `note` 로 남기라고 그 자리에서 처방한다.

### 실제로 분리 가능한 실패에 투자한다

| 실패 | 처방 |
|---|---|
| 컨테이너 크래시 | `restart: unless-stopped` + HEALTHCHECK + 배너 |
| 나쁜 스키마 변경으로 크래시루프 | 마이그레이션을 **별도 one-shot 컨테이너**로 분리 + 기동 전 DB 백업 + 롤백 명령. **셋 중 백업만 구현돼 있다 — 아래 각주** |
| 포트 선점 | 기동 시 확인 후 **사유를 남기고 종료** |
| 볼륨·DB 손상 | 6시간 `VACUUM INTO` + **매시간 판단 git 백업**. **넷 중 하나만 구현돼 있다 — 아래 각주** |
| 디스크 고갈 | 임계 감시 + 대시보드 배너 |
| 클라이언트·서버 버전 스큐 | `/healthz` 의 `api_version` 비교 → `additionalContext` 에 **명시 배너**. 플러그인은 자동 갱신되므로 스큐는 운영자가 아무것도 안 해도 발생한다 |
| 서버만 낡은 채로 돈다(플러그인은 갱신됐다) | 실행 파일 교체를 감지해 **검증 후 스스로 재기동**(아래). **단 플러그인 버전이 오르는 갱신은 이 축이 안 덮는다** — 런처가 짓는 이름에 소스 트리가 박혀 있고 `${CLAUDE_PLUGIN_ROOT}` 에 버전이 들어가므로, 갱신은 **다른 이름의 새 파일**을 만들고 도는 서버가 문 파일은 영영 안 바뀐다. 그 갈래는 `/healthz` 의 `self_update.uncovered` 가 말하고(화면은 `자동 갱신  **한 갈래를 못 덮는다**`) **재기동은 사람이 한다.** 감시를 아예 못 켜는 배치는 `self_update.reason` 이 사유를 말한다 |

**자기 갱신은 스큐 창의 `서버 몫`에만 상한을 선언한다** — `selfUpdateReactionBudget`
(주기 + 검증 상한 + 드레인 유예)이고, 시험이 그것을 실측 상한 아래로 붙든다(§10 3차 실측).
**창 전체가 유계라는 뜻이 아니다.** 두 자리가 그 밖에 있다:

- **상류.** 실행 파일을 다시 만드는 것은 `bin/fd` 런처이고 그것은 새 세션이 부를 때 돈다.
  그 지연에는 선언된 상한이 없고, 실측으로 사슬을 지배한다(§10 3차 실측).
- **버전이 오르는 갱신.** 런처의 산출물 이름에 소스 트리가 박혀 있어(위 바이너리 캐시 항목)
  플러그인 버전이 오르면 **키가 바뀐다** — 새 세션은 새 파일을 짓고 도는 서버의 자리는
  안 덮인다. 이 갈래에는 상한이 아니라 **사람의 재기동**이 처방이고, 그 사실을 서버가
  `self_update.uncovered` 로 말한다(2026-08-06 A/B 재현: 고정 이름이던 옛 판은 같은 자리가
  새 inode 로 덮여 30초 안에 자기 갱신이 돌았고, 지문 이름에서는 새 버전을 지은 뒤 75초가
  지나도 옛 파일의 inode·mtime 이 불변이고 `/healthz` 는 `watching=true` 뿐이었다).
- **검증이 거절한 판.** `selfcheck` 를 통과 못 하면 감시기가 그 판을 태우고(`lastFail`)
  **파일이 또 바뀌기 전까지 한 판도 더 안 돈다.** 그 구간의 스큐는 사람이 손댈 때까지 무한이다 —
  예산이 유계로 말할 것이 없는 유일한 갈래이고, 그래서 그 거절이 `/healthz` 에 남는다.

다른 스큐 원천에는 서버 몫의 상한조차 없다: MCP 는 Claude Code 재기동을, 컨테이너는 사람이
`docker compose up -d --build` 를 칠 때까지 기다린다. 그래서 위 행의 배너는 **안 없어진다.**

**⚠ 마이그레이션 행은 지금 구현과 어긋난다(2026-08-03 실측).** 이 문서를 근거로
"설계대로 돼 있다"고 믿는 것이 지금의 진짜 위험이라 여기 적는다.

| 처방 | 상태 | 실제 |
|---|---|---|
| 별도 one-shot 컨테이너로 분리 | **없음** | 적용이 `store.Open()` 안이고 그것이 `fd serve` 기동 경로다. 나쁜 증분은 "서버가 안 뜬다"로 나타난다 |
| 기동 전 DB 백업 | 있음 | `PlanMigration` 이 백업 여부를 판정하고 `VACUUM INTO` 로 뜬다(`<db>.bak-<UTC>`) |
| 롤백 명령 | **없음** | 되돌리는 서브명령이 없다. 되돌릴 길은 백업 파일 손 복사뿐이다 |

**지금 구조를 유지하기로 한 판단과 근거.** 증분은 이제 **네 단**(`002`·`003`·`004`·`005`)이고,
`005` 에서 **순수 가산이 아니게 됐다**(절대경로 발자국 삭제). 그래도 적용을 기동에 남긴다 —
적용을 떼면 **모든 명령**(fail-open 훅 4종 포함)이
"스키마가 아직 안 올라간 DB" 를 만나는 새 경로가 생기고, 훅은 정의상 조용히 죽으므로
그 경로의 실패가 침묵한다. 제거하는 위험보다 새로 만드는 위험이 크다.

**이 판단이 뒤집히는 조건은 하나다 — 증분이 파괴적(컬럼 삭제·타입 변경·데이터 이행)이 되는 순간.**
그때 `fd migrate [--to N]` / `fd migrate --rollback` 으로 적용을 기동에서 분리한다.

**그 순간이 실제로 왔다(2026-08-06, 증분 `005`).** `fd migrate` 를 짓는 대신 시험이 제시한
다른 갈래를 택했다 — 증분마다 **왜 되돌릴 수 있는지를 적고 예외로 두는 것**이다.
`migrate_guard_test.go` 의 `destructiveExempt` 가 증분 번호 → (허용 조작, 사유) 를 담고,
**사유가 비면 예외로 안 쳐 준다.** 예외의 키는 사람이 읽는 라벨이 아니라 op 상수다 —
라벨 문자열에 결합하면 라벨을 한 글자만 고쳐도 예외가 조용히 안 맞게 된다.
구조가 사라지는 조작(`DROP TABLE`·`DROP COLUMN`·`RENAME`)은 `neverExempt` 라 그 예외로도 못 연다:
그 셋은 "다른 시험이 본다"고 적혀 있었으나 증분에 넣어 실제로 돌려 보니
`TestFreshInstallAndUpgradeProduceTheSameSchema` 와 `TestDeclaredTablesMatchDesign` 이
**둘 다 통과했다**(신규 설치와 판올림이 양쪽 다 그 증분을 돌아 스키마가 똑같이 줄고,
표 수 시험은 증분 텍스트의 `CREATE TABLE` 만 센다). 없는 안전망을 믿는 대신 목록으로 막는다.

`fd migrate [--to N]` / `--rollback` 은 **여전히 없다.** 되돌릴 길은 판올림 전 자동 백업
파일을 손으로 복사하는 것뿐이고, 그것이 `005` 의 예외를 정당화하는 근거 ⒞ 다.

**그 조건은 문서가 아니라 시험이 지킨다** — `internal/store` 의 `TestBundledMigrationsAreAdditive`
가 번들된 증분 전부를 훑어 파괴적 조작(표·컬럼 삭제, 개명, `DELETE FROM`, `UPDATE … SET`,
`INSERT … SELECT`)을 찾고, 걸리면 (a) 적용 분리(`fd migrate`, 아직 없다) · (b) 예외 등재
(`destructiveExempt` 에 사유와 함께) 두 처방을 그 자리에 띄운다. 만료 조건이 산문에만 있으면
그 순간을 아무도 안 보고, 그러면 **만료된 판단 위에서 계속 돈다** — 이 각주가 없애려는 위험이
바로 그것이다. (주석은 걷어내고 본다. 이 레포의 증분은 본문보다 주석이 길고 그 주석이
"무엇을 안 하는지"를 설명하느라 파괴적 낱말을 자주 쓴다.)

그 전까지 "롤백 명령" 자리는 **문구가** 메운다: 마이그레이션이 깨지면 오류와 ERROR 로그가
`store.RollbackHint` 로 **백업 파일 경로와 되돌리는 정확한 절차**(`-wal`·`-shm` 제거 포함)를 함께 낸다.
명령이 없다면 적어도 절차가 실패한 그 자리에 있어야 한다. 그 자리가 비어 있던 것이 앞선 판의 결함이다 —
업그레이드 경로가 백업 경로를 지역 변수로 버려, 정확히 이 표가 겨냥한 상황에서
유일한 탈출구의 좌표가 사라져 있었다.

### 서버는 자기 실행 파일 교체를 감지해 스스로 재기동한다

`fd serve` 가 주기적으로 자기 실행 파일을 재고, 바뀌었으면 `fd selfcheck` 를 **자식으로 돌려
검증**한 뒤 드레인하고 `syscall.Exec` 한다. 재기동한 프로세스가 DB 를 열면서 증분이 자연히
적용된다. 이것이 없으면 `plugin update` 뒤 훅과 클라이언트만 새것이 되고 **서버는 낡은 채로 남는다** —
위 표의 버전 스큐 행이 배너로만 막던 자리다. **MCP 는 여전히 Claude Code 재기동이 필요하다**(별개 축).

- **드레인은 인플라이트를 마무리한다 — 자르지 않는다.** 요청 컨텍스트는 서버 수명 ctx 의
  자손이 **아니다**. 종료는 두 단이다: ① 수명이 정해지지 않은 응답(SSE)에 종료를 알리고
  남은 요청을 유예(`api.ShutdownGrace`, 10초) 안에서 기다린다 ② 유예를 넘긴 것만 끊고
  **그 사실을 ERROR 로 말한다**. ①이 없으면 SSE 구독 하나가 유예를 통째로 쓴다 —
  `srv.Shutdown` 은 요청 컨텍스트를 안 끊으므로 스트림이 스스로 나가는 다른 길이 없다.
  **종료 통지는 요청 컨텍스트와 다른 축이다**: "서버가 종료 중이다"와 "이 요청은 그만둬도
  된다"를 한 값으로 접으면 드레인이 곧 절단이 된다 — 앞선 판이 정확히 그 모양이었고,
  주석 셋과 계획·스펙이 서로 다른 말을 하는 상태로 랜딩까지 갔다. 그 절단을 정당화하던
  근거("아웃박스가 덮는다")도 틀렸다: **절단은 미도달이 아니라 서버가 답한 500 이라
  아웃박스도 낡음 배너도 안 탄다.** 이 유예는 **자기 갱신 반응 시간의 항**이고,
  컨테이너의 `stop_grace_period` 는 그보다 커야 한다.
- **감지 신호는 소스가 아니라 자기 실행 파일이다.** 빌드는 `bin/fd` 런처가 이미 한다.
  서버에 빌드 로직을 넣으면 사다리가 두 벌이 되고, 이 레포는 그 표류를 세 번 겪었다.
  `/healthz` 의 빌드 좌표를 트리거로 **안 쓴다** — 플러그인 캐시에 `.git` 이 없어 실제 사용자
  환경에서 그 좌표가 **항상 부재**다.
- **소스 지문이 박힌 자리는 버전 갱신을 못 덮는다 — 그 갈래를 이름 붙여 화면에 낸다.**
  감지 신호가 "이 **자리의** 파일이 바뀌었나"인데 런처가 소스 트리마다 다른 이름을 짓기 때문에,
  플러그인 버전이 오르면 **다른 파일**이 생기고 이 자리는 안 바뀐다. 그때 감시기는 영원히
  "그대로다"를 내는데 그것을 `watching=true` 만으로 말하면 아래 컨테이너 갈래와 똑같은
  **틀린 안심**이다. 같은 소스 트리의 재빌드(개발 워크트리·`git pull`)는 여전히 이 자리를
  `mv -f` 로 덮어 사슬이 정상으로 도니 **감시를 끄지는 않는다** — `watching=false` 는 과보고다.
  대신 못 덮는 갈래를 `self_update.uncovered` 라는 **Stalled 와 다른 축**으로 내보낸다
  (Stalled 는 "지금 못 잰다"는 회복되는 고장, 이것은 회복이 없는 성질이라 처방이 갈린다).
  ★ **고정 포인터를 exec 하거나 `bin/` 안 최신 mtime 을 감시하는 쪽으로 풀지 않는다.**
  그러면 **워크트리 빌드 한 번이 설치본 서버를 그 브랜치 판으로 갈아치운다** — 위 바이너리
  캐시 항목이 방금 없앤 교차 오염(먼저 지은 쪽이 전 채널을 대표한다)이 자기 갱신 경로로
  되살아나고, 이번에는 훅·MCP 가 아니라 **도는 서버가** 핫스왑된다. 심볼릭 링크로 우회하는
  길도 없다: 리눅스의 `os.Executable` 은 `/proc/self/exe` 를 읽어 링크를 **푼 실체 경로**를
  주므로 링크로 exec 해도 감시 자리는 여전히 지문 이름이다. 신호를 넓히려면
  "`BinCacheDir` 안 최신 `fd-*`"를 봐야 하는데 그것이 곧 그 교차 오염이라, 값을 치를 설계가
  따로 필요하다 — **이 판에서는 안 했고, 복원은 fd 큐의 후속으로 남겼다.**
  ★ **그 후속이 돌아왔고 답은 기각이다(2026-08-07). 다시 열려면 아래를 먼저 뒤집어라.**
  트리거를 "내 후계자인 `fd-*`" 로 넓히는 후보 둘을 실제로 따졌고 **둘 다 같은 자리에서
  걸린다: 후계자를 알아보는 단서가 경로 모양뿐이다.** 키에서 버전 성분만 바꾸는 쪽은
  bincache.go 의 "키를 해독하지 않는다 — 역함수를 Go 에 두면 규칙이 두 벌이 된다"에 걸리고,
  `${CLAUDE_PLUGIN_ROOT}` 의 형제 버전 디렉토리를 훑는 쪽은 `LegacyOutboxDirs` 가
  `~/.claude/plugins/data/*/flightdeck` 를 glob 하지 않기로 하며 못 박은 금지(§13 — 그 경로에는
  플러그인 버전과 마켓 이름이 들어간다)에 **그대로** 걸린다. 바로 위 「옛 자리는 이관하지
  않는다」의 `LegacyBinDirs` 와 갈리는 지점이 여기다: 그쪽은 목록을 **다 찍고 아무것도 안
  고르지만**, 트리거는 **하나를 골라 exec 해야** 한다.
  ★ 그리고 어느 후보 규칙을 쓰든 최종 선택은 mtime 인데 **mtime 최신은 최신 버전이 아니다** —
  옛 `${CLAUDE_PLUGIN_ROOT}` 를 쥔 세션이 훅을 한 번 돌리면 옛 키가 새 mtime 을 얻어 서버가
  옛 판으로 내려가고, 새 세션이 새 키를 지으면 또 올라간다. 회차마다 드레인+재기동이 도는
  **깜빡임**이라 지금의 침묵보다 명백히 나쁘다. 검증은 이것을 **못 거른다**:
  `verifyWithSelfcheck` 가 보는 `fd selfcheck ok build=` 한 줄은 **어느 브랜치의 fd 든** 낸다.
  즉 후보 선정 규칙이 유일한 방어선인데 그 규칙이 전부 추측이다.
  **남는 결론: 버전이 올라도 살아남는 계보 식별자가 이 시스템 어디에도 없다.** 버전은 경로에
  있고 그 경로가 곧 키이며, 설계는 그 경로 모양을 되짚는 것을 금지한다. 그러니 이것은
  트리거에서 풀 문제가 아니라 **런처 쪽에 버전과 무관한 플러그인 정체를 새로 만드는 설계
  변경**이다. 그 변경이 오기 전까지 답은 `self_update.uncovered` 이고 처방은 **사람의
  재기동**이며, 트리거는 여전히 `w.exePath` **한 자리**다 —
  `TestWatcherMeasuresNothingButItsOwnPath` 가 그것을 잠근다(step 한 회차가 재는 경로가
  `w.exePath` 뿐임을 단정한다).
  기각 사유 전문과 실측(옛 루트를 쥔 채 살아 있는 프로세스 · `-trimpath` 로 사라지는 소스 경로 ·
  이 머신의 워크트리 벌 수)은 **selfwatch.go 의 `selfUpdateStatus.Uncovered` ★★ 에 있다 —
  사본을 만들지 마라. 판정은 한 자리에만 산다.**
- **컨테이너는 자기 갱신을 안 한다.** 이미지는 불변이라 실행 파일이 영영 안 바뀌고, 그 상태로
  "보는 중"이라고 말하면 읽는 쪽은 따라오고 있다고 믿는다 — 침묵보다 나쁜 **틀린 안심**이다.
  갱신 경로는 `docker compose up -d --build` 이고, **그 사실을 화면이 말한다**(`self_update.reason`).
- **`syscall.Exec` 이 없는 플랫폼도 같다** — 안 켜고 사유를 낸다. no-op 으로 접지 않는다:
  빈 성공을 내면 호출부가 **드레인까지 마친 뒤** "재기동했다"로 읽고 서버는 내려간 채 남는다.
- **롤백 자리를 안 만든다.** 죽은 프로세스는 자기를 못 되돌린다 — supervisor 를 새로 만드는 일이 된다.
  검증이 그 자리를 대신한다: 새 바이너리가 `selfcheck` 를 통과 못 하면 재기동을 **거절**하고
  옛 프로세스가 계속 돈다(`self_update.outcome=refused`).

**이 축은 MCP 도구를 안 늘렸다**(§1 원칙 ②). 늘어난 것은 사람이 안 부르는 서브명령 하나(`selfcheck`)뿐이다.

**판단 백업이 유일하게 재생성 불가한 자산이다.** `judgment`+`snapshot` 을 매시간 마크다운/JSONL 로
내보내 별도 bare git 레포에 커밋한다. **DB 와 같은 볼륨에 두지 않는다.**

**다만 그 문장의 대상은 좁다.** `judgment`+`snapshot` 만으로는 복원이 안 된다 —
`judgment.project → project`, `judgment.session_id → session`, `session → machine`,
`snapshot.project → project`, `judgment.supersedes → judgment` 가 전부 FK 이고
`foreign_keys=1` 이 항상 걸린다. 그리고 **`session.id` 는 서버 발급 ULID 라 새 DB 에서 재현할 수
없다** — `project`·`machine` 은 사람과 클라이언트가 정한 이름이라 다시 부를 수 있지만 세션은 아니고,
판단의 85%가 그것을 가리킨다. 그래서 구현된 `fd export --judgments` 는 **폐포 여섯 표를 통째로 담는다.**
그리고 형식은 마크다운이 아니라 **JSONL 하나**다.

**열화 경로를 시험으로 강제한다** — 서버를 죽인 상태에서 `open → note(아웃박스) → pick(캐시 또는 거절) → finish(거절) → 재기동 → 재생`
전 경로가 성공하는 통합 시험을 둔다. 열화 경로는 안 돌리면 썩고, 그러면 정확히 필요한 순간에 없다.

## 8. 프로젝트 등록

정본은 레포 안의 커밋된 `.flightdeck.yaml` 이고 서버 DB 는 캐시다. 서버가 저장하는 것은
`path`·`remote_url`·`default_branch`·시크릿의 호스트 경로뿐이며, 나머지는 **대상 ref 의 파일에서 읽는다**(로컬 사본을 믿지 않는다).

```yaml
schema: 1
name: <프로젝트 이름>
default_branch: main

labels:
  values: [...]         # 표시 전용. 어떤 배제 판정에도 안 쓴다
  strict: false         # 기존 항목을 거절하면 큐가 통째로 막힌다

counters: [contract_revision]

# ── 아래는 Tier B 부터 ───────────────────────────
verify:
  kind: local           # none | local
  command: "make ci"
  ok_line: '^CI OK: .* dev-[0-9a-f]{7,}$'   # 줄 전체 정규식 · 매치 정확히 1개
  tail_lines: 60
  budget: 45m

secrets:
  sign: ".local/cosign" # 병합 잡에만
  env:  ".local/dev.env" # 실행 잡에만

approval_paths:         # 이 경로를 고친 브랜치는 자동 실행 거절 → 사람 승인
  - "Makefile"
  - ".flightdeck.yaml"

resources:
  - id: staging
    why: "단일 클러스터 — 이미지 태그·데이터·포트가 전부 고정 좌표다"

recipes:
  staging-e2e:
    resource: staging
    run: "<한 줄이 한 잡이다>"     # 개별 명령을 쪼개면 사이에 다른 잡이 끼어든다
    timeout: 60m
```

**검증 통과 판정은 종료코드가 아니라 `ok_line` 이 마지막 `tail_lines` 줄에 정확히 1회 매치되는 것이다.**
그 규율은 종료코드를 믿었다가 두 번 거짓 보고를 낸 경험이 만들었다.
그리고 경계 마커는 **줄 전체 정규식 + 매치 1개 단정**으로 찾는다 — 부분 문자열로 찾으면 그 문구를 인용한 산문이 경계를 옮긴다.

## 9. 이관과 공존

**dual-read, single-write. 최소 한 달.**

`fd` 는 DB ∪ 레거시 파일을 함께 읽어 판정하고 **쓰기는 DB 로만** 한다.
옛 도구로 계속 일하는 세션의 상태도 `fd` 세션에게 보인다.

**옛 도구를 지우지 않는다.** 되돌릴 수 없는 이관은 1인 운영에서 착수 자체가 안 된다 —
실패하면 그날 전 세션이 멈추고 복구할 사람이 하나뿐이다.
`fd export --to-legacy` 가 옛 형식으로 되쓴다.
`fd export --judgments` 는 판단 원장을 JSONL 로 낸다(§7 의 백업 축이다 — 이관과 무관하다).

`fd import --dry-run` 이 먼저다. **건수 대조표 + 해석 실패 전량 목록.**
조용히 버리는 것이 하나도 없어야 한다.

- 비규약 절은 **버리지 않고 절 이름 그대로 보존한다** — 규율이 실무보다 좁았다는 증거이지 오류가 아니다.
- 핸드오프 산문은 **파싱하지 않고 통째로 blob** 이다. 구조화하면 세션들이 스스로 발명한 절이 갈 곳을 잃는다.
- 형식 위반은 **거절하고 로그에 남긴다** — 조용히 고치면 그게 또 하나의 손 기재다.

매일 자동 대조(추천 일치율 · 생존 집합 · 대시보드 생성물 vs 손 편집)를 돌리고,
**3일 연속 일치하면** 그 자리의 손 편집을 막는다.

## 10. 계측 — 어떤 처방이 나았는지 판정할 유일한 축

기존 구조는 락 다섯 개 중 ttl 근거 주석이 있는 것이 하나뿐이고, 검증 단계별 수치가 하나뿐이며,
락 대기는 산문을 grep 해 세는 수밖에 없어 **"기다렸으나 안 적은 세션"이 원리적으로 관측 불가**였다.

`event` 테이블에 **완전 자동·추가 전용**으로 쌓는다. 로그가 또 하나의 손 관리 대상이 되면 안 된다.

- 자원 획득·대기·반납
- 큐 판정 결과(탈락 사유 분포)
- 세션당 쓰기 호출 수 — **원칙 ②의 성공 지표**
- 세션당 판단 바이트 — **0 에 수렴하면 이 설계가 지키려던 것이 사라지는 중이다**
- 알림 확인율 — 무시율이 오르면 그 사실이 지표로 드러난다.
  기존 무갱신 경고가 상시 점등돼 판별력을 잃은 실패를 반복하지 않기 위해서다
- `work_to_main_seconds` — 착수부터 랜딩까지. **이 설계를 반증할 유일한 축**
- **세션 카드 파생의 횟수·세션 수·시간**(`/metrics` 의 `flightdeck_session_card_derives_total` ·
  `flightdeck_session_cards_total` · `flightdeck_session_card_derive_seconds_total`).
  이 서버에서 가장 비싼 일이 git 저장소 전수 훑기인데 그 비용이 어느 화면에도 안 떴다 —
  그래서 꼬리가 도구 호출마다 그것을 한 번씩 더 돌리는 동안 아무도 몰랐다.
  요청 지표(`flightdeck_request_duration_seconds`)와 **다른 축**이다: 그쪽은 라우트별 총 시간,
  이쪽은 그중 파생이 먹은 몫이라 둘을 겹쳐 봐야 "느린 것이 파생인가"가 갈린다
- 처방 발화·확인율 — `prescribe` 대비 `prescribe_ack`. **떨어지면 조건을 줄인다, 문구를 키우지 않는다**
- 사건이 있는 세션 비율 — 착수 시점 19건 중 1건

### 1차 실측 (2026-08-04, 관측 33시간)

근거 없는 상수 셋의 근거를 만들었다(`fd-live-window-baseline` · `fd-prescribe-threshold-baseline`).
**재료는 `event` 표뿐이다** — `signal` 표는 PK 가 `(session_id, kind)` 라 종류별 한 행이고 갱신되므로
이력이 없다. 이력은 `event(kind='session.beat')` 에 있고 `Service.Beat` 호출마다 1행이라 스로틀이 없다.
따라서 재현은 DB 파일 하나만 있으면 되고 서버를 안 띄워도 된다.

| 상수 | 값 | 무엇을 쟀나 | 결과 |
|---|---|---|---|
| `service.DefaultLiveWindow` | 2h (유지) | 침묵 W 뒤 복귀율, 검열 보정 | 1h 24.7% · 1.5h 14.0% · **2h 11.3% · 3h 11.3%** · 4h 6.4% |
| `judge.SilentNewPaths` | 12 (유지) | 판단 사이 새 경로 분포 109구간 | p50 0 · p90 6 · p95 15 → 임계 12 는 6.4% 를 자른다(≈p94) |
| `judge.SilentGap` | 60m (유지) | 판단 사이 간격 분포 62구간 | p50 8.0m · p90 45.9m → 임계 60m 는 8.1% 를 자른다(≈p92) |

셋 다 값을 안 바꿨다. 바꿀 이유가 없었다는 것이 결과다 — 그러나 **두 전제가 반증됐고 그쪽이 더 중요하다.**

1. **창은 화면 크기의 지렛대가 아니다.** 2시간을 고른 근거는 "8시간일 때 19건이 떠서 못 썼다"였는데,
   2시간으로도 보드는 p90 16건 · 최대 23건이다. 이 머신이 실제로 20건 안팎을 동시에 돌리기 때문이다.
   창을 더 줄이면 사는 것은 p90 16→12 뿐이고 지불하는 것은 복귀율 11.3%→24.7% 다.
   화면 크기는 예산 접기와 정렬로 다뤄야 한다.
2. **처방 확인율의 병목은 임계가 아니라 `overlap` 이다.** 발화 55건 중 overlap 31건(56%)의
   확인율이 **0/31** 이다. silent 는 9건뿐이고(세션당 1건 미만) 임계를 더 올려도 확인율은 안 오른다 —
   사라질 뿐이다. "떨어지면 조건을 줄인다"를 이 자리에 그대로 적용하면 **엉뚱한 상수를 줄이게 된다.**
   그리고 `PrescribeMax=3` 이 막으려던 "리팩터 한 턴이 outside 수십 건" 은 일어난 적이 없다 —
   outside 는 전 기간 2건이고 둘 다 확인됐다. 접기가 걸린 턴은 35개 중 2개다.

   **★ 접기 재측(2026-08-06) — 위 "35턴 중 2개"는 낡았고, 그 사이 접힘은 소실이었다.**
   표본이 발화 55건에서 239건으로 늘어난 뒤 다시 쟀다(턴 = 같은 세션·같은 초의 `prescribe`
   이벤트 묶음): **턴 129개 중 접힌 턴 15개(11.6%)**, 한 턴 최대 **7건**.
   접혀서 사라지던 축은 `overlap` 11 · `unclaimed` 11 · `silent` 4 · `outside` 2 다.

   **늘어난 원인은 `lane-turn` 이 아니라 표본이다.** 원장에 lane-turn 처방은 **전 기간 0건**
   이고(`kind='prescribe'` 257건 시점의 축 분포: overlap 138 · unclaimed 67 · silent 37 ·
   outside 15), 코드도 상시가 아니라 줄 행마다 1회다. 그래서 **이 축의 접힘 위험은 아직 한 번도
   실측된 적이 없다** — 아래 기구는 다른 네 축에서 관측된 것이고 lane-turn 에 대해서는 코드를
   읽어 세운 추론이다.

   더 나쁜 것은 빈도가 아니라 **기구**였다. 접힌 것까지 발화 기록하는 계약(`PrescribeMax`
   주석)과 `suppressed` 가 silent 외 모든 키를 무조건 누르는 규칙이 만나, **접힌 처방은 그 키에
   대해 영구히 사라졌다** — 세션은 문구를 한 번도 못 보고 원장에는 "정상적으로 접혔다"로만
   남는다. 사라지던 28건 중 11건(**39%**)이 `unclaimed` 로 `overlap` 과 동률이고, 그 축은
   `silent` 와 달리 해제 규칙이 없어 한 번 접히면 그 세션에서 다시 안 뜬다.

   **그래서 계약을 뒤집었다: 표시된 것만 발화로 센다.** 상한은 무의미해지지 않는다 —
   **순환한다.** 표시된 셋만 눌리므로 **그 축의 입력이 다시 생기는 턴**에 접혔던 것이 올라온다.
   §4 가 고발한 상시 점등은 **같은 것이 매 턴 반복되는 것**이라 이 동작과 다르고, 그 경계를
   `TestFoldedPrescriptionsAreNotRecordedAndComeBack` 이 단정한다(둘째 턴에 같은 경로를 전부
   다시 만져도 뜨는 것은 접혔던 것뿐이다).

   **⚠ 다만 "결국 전부 나온다"는 조건부다.** `TurnPaths` 가 `f.LastAt.After(since)` 로 뽑히고
   `since` 가 마지막 발화 시각이라, **한 턴에 몰아친 outside 다발**은 그 경로를 다시 만지지
   않는 한 여전히 안 돌아온다. 하필 그것이 `PrescribeMax` 가 애초에 겨냥한 시나리오다
   (후속: `fd-folded-outside-burst-still-lost`).

   **⚠ 그리고 이 개정의 근거였던 측정을 이 커밋이 닫았다.** 표시분만 기록하므로 한 턴의
   `prescribe` 이벤트 수가 구조적으로 3 을 못 넘고, `folded` 는 원장에 안 실린다 —
   **위 129/15 는 마지막으로 잴 수 있었던 값이다.** 다시 재려면 folded 를 원장에 실어야 한다
   (후속: `fd-folded-count-left-no-ledger-trace`).

   기각한 둘: **축별 쿼터** — `overlap` 이 상대 수만큼 늘어 다른 축을 미는 구조는 실재하지만
   (실측이 그 그림이다), 소실이 막힌 뒤엔 그 축의 입력이 다시 생기는 한 순환이 결국 낸다.
   쿼터는 그 위에 기구를 하나 더 얹는 것이라 값이 붙을 때 따로 판정한다. **요약 줄에 접힌 키
   적기** — 접힌 것이 다시 뜨게 된 지금은 세션이 결국 그 문구를 보므로, 키를 나르는 배선
   (service → api → 훅 렌더)을 새로 깔 이유가 사라졌다. 요약 줄에서는 **거짓이 된 문장 하나만**
   고쳤다("접힌 것도 이미 발화된 것이라 다시 안 뜬다" → "발화로 안 세므로 같은 조건이면 다시 뜬다").

### 2차 실측 (2026-08-05) — 위 ②의 귀속이 틀렸다

`fd-prescribe-overlap-ack-zero` 가 그 0/31 을 다시 쟀다. **무시가 아니라 구조였다.**

| 잰 것 | 값 |
|---|---|
| 카드 133장 중 — 발자국만(판단 0) | **51장** |
| 판단만(발자국 0) | **46장** |
| 둘 다 있는 카드 | **6장** |
| overlap 을 맞은 카드 7장의 판단 수 | **전부 0**(발자국은 1~62개, 형제 카드는 판단 12~31개) |

발자국은 훅이 쓰고 판단은 MCP 가 쓴다. 한 대화의 정체가 카드 둘로 갈리면 처방은
**발자국 카드**에서 뜨고 ack 은 **판단 카드**에 꽂힌다 — overlap 확인율은 행동이 아니라
**원리적으로** 0이다. 문구를 고쳐도 임계를 올려도 안 움직인다.

**그래서 이 절의 "알림 확인율"은 지금 무엇을 재고 있는지 조심해야 한다.** 세션이 처방을
따르는지가 아니라 **카드가 안 갈렸는지**를 재고 있다. 갈림의 원인은 `07e5df4`(cc 표류)와
`4de4b21`(워크트리 축)이 고쳤으므로, 이 수치는 **그 뒤로 다시 재야** 뜻이 생긴다.

**두 번째 사례가 생겼다(2026-08-06) — 이번엔 카드 갈림이 아니라 통로다.** `e72f2be` 가 넣고
`90dbeb7` 이 배선한
`lane-turn` 은 행동으로 `land()` 를 지정하는데 **land 경로는 ack 통로를 안 지난다**(ack 을
남기는 것은 판단을 쓰는 `note`·`finish` 뿐이다). 그리고 `ackPrescriptions` 는 키를 안 가리고
그 세션에 열린 것을 **전부** 닫으므로, 레인과 아무 상관 없는 note 한 줄이 `lane-turn:<행>` 을
확인 처리한다. 이 키에 대해 확인은 **정확히 반대 신호**다 — 처방대로 랜딩한 세션이 미확인으로
남고, 처방을 무시하고 판단만 남긴 세션이 확인으로 잡힌다.

**고치기 전에 적는다.** 통로 뚫기(land 가 자기가 응답한 키만 골라 ack)는 선언 경로 밖이라
후속 항목으로 올렸고, 여기서 한 것은 **지금 무엇을 재는지를 코드와 이 절에 적고 그 사실을
시험으로 잠근 것**(`TestLaneTurnAckMeasuresJudgmentsNotTheLandItPrescribed`)뿐이다. 그 시험은
계약이 아니라 현재 사실을 잠근다 — 통로를 뚫으면 먼저 빨개지고, 그때 고칠 것은 시험이 아니라
여기 적힌 서술이다. 수치를 그대로 두고 설명을 안 적는 것이 이 레포가 가장 비싸게 보는 결함이다.

**그리고 "확인율"이라는 이름이 두 가지를 가리킨다.** `AckReach`(board.go)는 키를 안 보고
**세션 단위**로 센다 — 위 ②의 "overlap 0/31" 같은 **키별** 확인율을 내는 코드는 어디에도 없고,
그 수치는 사람이 따로 잰 값이다. 둘을 같은 이름으로 읽으면 이 절의 값을 코드로 재현하려다
다른 값을 얻는다.

## 12. 시험 규율

- **판정 로직은 시험이 부르는 순수 함수에 있어야 한다.** 판정이 본문에 흩어지면 시험이 그 로직의 **사본**을
  단정하게 되고, 변이가 조용히 새어 나간다. `internal/judge` 가 그 자리다.
- **다중 조건은 사유 문자열을 반환한다.** 공허한 단정(결과만 찍고 왜인지 안 남기는 것)이 통과하지 못하게.
- **단정은 소비자의 좌표계로 쓴다.** 구현의 개념을 빌려 쓰면 자기가 막는다는 축을 원리적으로 못 본다.
  대상은 **MCP 응답 문자열 · 훅 stdout · SSE 한 줄 · `additionalContext` 본문 · 구조화 로그 실물 한 줄**이다.
- **새 검사는 망가진 것을 넣어 빨간불을 먼저 확인한다.** 초록만 보고 통과로 단정하지 않는다.
- 열화 경로(§7)와 이관(§9)에 통합 시험을 둔다.

## 13. 플랫폼 실측 — 확인된 것과 아직 아닌 것

**추측을 사실로 적지 않는다.** 아래는 이 설계가 기대는 플랫폼 동작이다.

### 확인됨 (Claude Code 2.1.220, 2026-08-03 실측 — ③ 은 2.1.221, 2026-08-04 실측)

**① MCP stdio 서버는 세션 식별자를 환경으로 받는다.**

claude 가 띄운 stdio MCP 서버 프로세스의 환경에 다음이 있다:

```
CLAUDE_CODE_SESSION_ID=<이 세션의 UUID>     ← 세션 정체의 원천
CLAUDE_PROJECT_DIR=<프로젝트 루트>
CLAUDECODE=1 · CLAUDE_CODE_ENTRYPOINT=cli · CLAUDE_CODE_SSE_PORT=<포트>
```

그리고 cwd 가 프로젝트 디렉토리다. `CLAUDE_CODE_SESSION_ID` 가 그 세션의 실제 id 와
정확히 일치하는 것을 확인했다.

**그래서 훅 발급 토큰 파일과 MCP 도구의 `session` 인자를 만들지 않는다.**
`fd mcp` 가 기동 시 환경에서 읽는다. 파생 가능한 것에 인자를 만들지 않는다는 원칙 ①이
여기에도 그대로 적용된다 — 인자가 있으면 틀린 값이 들어올 수 있다.

> **이 확인 과정에서 대조를 한 번 틀렸다.** 처음 잰 MCP 프로세스는 `CLAUDE*` 가 0개였는데,
> 부모 사슬을 보니 **Cursor 가 띄운 것**이었다. 그 상태로 "세션 식별자가 안 온다"는
> 정반대 결론을 낼 뻔했다. 프로세스를 잴 때는 **그것이 정말 대상의 자식인지부터 증명한다.**

**② 플러그인의 `bin/` 은 Bash 도구 PATH 에 붙는다.**

활성 플러그인 전부의 `<캐시>/<마켓>/<플러그인>/<버전>/bin` 이 PATH 에 선행 등록된다
(`bin/` 이 실제로 없는 플러그인의 경로까지 들어간다). **버전이 경로에 들어간다** —
플러그인이 갱신되면 경로가 바뀌므로 그 경로를 어디에도 저장하지 않는다.

**훅은 그래도 `${CLAUDE_PLUGIN_ROOT}/bin/fd` 절대경로를 쓴다.** 훅 실행 환경이
Bash 도구와 같다는 보장이 없고, 절대경로는 어느 쪽에서든 작동한다.
바로 부르는 `fd` 는 사람이 터미널에서 쓰는 경로다.

**③ `Stop` 훅의 stdin 은 세션 id 를 실어 오고, 그 stdout 주입은 모델을 다시 부른다.**

프로젝트 `settings.json` 의 임시 훅으로(플러그인 릴리스 없이) 잰다 — 계획 Task 1 참고.

stdin 페이로드가 싣는 키: `session_id` · `transcript_path` · `cwd` · `prompt_id` ·
`permission_mode` · `effort{level}` · `hook_event_name` · `stop_hook_active` ·
`last_assistant_message` · `background_tasks` · `session_crons`.
**`session_id` 가 실제로 온다** — 이 채널에 한해 확인됐다. `SessionStart`·`UserPromptSubmit`·
`PostToolUse`·`PreCompact` 네 채널의 stdin 은 이 축을 아직 못 쟀다(아래 "아직 아님" 3).

stdout 은 주입된다 — `hookSpecificOutput.additionalContext` 로, 모델에는 `<system-reminder>` 로 도착한다.

> **★★ 주입은 붙기만 하는 게 아니라 모델을 다시 부른다.** `additionalContext` 가 실리면
> 그것이 새 assistant 턴을 낳고, 그 턴은 다시 `Stop` 으로 끝나 또 주입한다 — **가드가 없으면
> 무한 루프다.** 무가드 판을 실제로 돌려 루프를 냈고, 사람이 인터럽트로 끊어서야 멈췄다.
> 재진입한 호출에는 `stop_hook_active` 가 `true` 로 온다. `cmd/fd/hook.go` 의 `hookStop` 이
> 이 값을 확인해 재진입이면 아무것도 안 낸다 — **이 가드가 없으면 이 기능 전체가 세션을
> 못 쓰게 만든다.**

### 플랫폼 동작은 표류한다 — 탐지를 한 자리에 모은다

세션 식별 하나만 봐도 이 판(2.1.220)에는 `CLAUDE_CODE_SESSION_ID` 가 직접 오는데,
불과 몇 판 전에는 그 변수가 없고 다른 환경변수의 **경로 안에** UUID 가 들어 있었다.
즉 이 축은 이미 한 번 바뀌었고, 옛 방식으로 뽑는 코드는 지금 **조용히 빈 값을 돌려준다.**

그래서 이 설계는 플랫폼 탐지를 **한 파일에 모으고, 못 찾으면 조용히 넘어가지 않는다** —
`fd doctor` 가 각 축을 실제로 재서 무엇이 관측됐고 무엇이 안 됐는지 이름으로 낸다.
부재를 기본값으로 접으면 그 사실이 영영 안 보인다.

**그리고 남의 플러그인 코드를 플랫폼 동작의 근거로 쓰지 않는다.** 그것은
"저 코드가 그렇게 가정했다"의 증거이지 "지금 판이 그렇다"의 증거가 아니다 —
그 플러그인이 유지되고 있는지조차 이쪽에서 알 수 없다. 근거는 이 머신에서 직접 잰 것만 쓴다.
